背景与动机

HM 要兼顾静态类型检查与简洁的程序书写：在执行前检查类型是否匹配，同时减少程序员手写类型标注的负担。它结合类型推断与参数多态，让系统根据定义和使用关系推断类型，并让同一个定义适用于多种类型。

例如恒等函数只需写一次，无需为整数、布尔值分别定义版本，也无需先指定参数类型。HM 的目标还包括推断出最一般的合法类型，避免加入程序本身没有要求的限制。为使这件事能够自动完成，HM 对多态作了限制：主要在 let 绑定处泛化，函数参数保持单态，类型方案的全称量词只放在最外层。

从恒等函数理解类型推断与主类型

let id = fun x -> x

假设参数 x 的类型是未知的 α\alphaα。函数体返回同一个 x，因此结果类型也必须是 α\alphaα，得到 α→α\alpha \to \alphaα→α。这里的类型变量记录类型之间的关系；

在这个无外部依赖的 let 定义中，可以得到类型方案 ∀α. α→α\forall\alpha.\,\alpha\to\alpha∀α.α→α：对于任意类型，都能把这种类型的值原样返回。不同使用处可以分别选择类型：

使用 本次使用的函数类型 结果类型
id 3 Int→Int\mathrm{Int}\to\mathrm{Int}Int→Int Int\mathrm{Int}Int
id true Bool→Bool\mathrm{Bool}\to\mathrm{Bool}Bool→Bool Bool\mathrm{Bool}Bool

同一次使用中，两个 α\alphaα 必须替换成同一类型；因此 Int→Bool\mathrm{Int}\to\mathrm{Bool}Int→Bool 不是该方案的实例。不同使用处则可以分别实例化，这不要求在运行时检查输入类型。

主类型方案是最一般的合法类型方案：其他合法类型都可由它实例化得到。例如，只写 Int→Int\mathrm{Int}\to\mathrm{Int}Int→Int 虽然适用于恒等函数，却额外限制了参数类型。HM 推断尽量保留程序没有限制的自由度。

单态类型与类型方案

单态类型 τ\tauτ 不含全称量词，但可以含尚未确定的类型变量。例如 Int\mathrm{Int}Int、α\alphaα、α→α\alpha\to\alphaα→α 都是单态类型。“单态”不等于“所有类型都已具体确定”。

类型方案 σ\sigmaσ 在单态类型外层量化若干变量，例如 ∀α. α→α\forall\alpha.\,\alpha\to\alpha∀α.α→α。使用方案时，可以把量化变量实例化为所需的单态类型；每次使用可独立选择，同一次实例化须一致替换同一个变量的所有出现。

单态类型 τ ::= α | Int | Bool | τ → τ
类型方案 σ ::= τ | ∀α. σ

在 HM 中，量词只能连续出现在最外层。因此 ∀α.∀β. α→β→α\forall\alpha.\forall\beta.\,\alpha\to\beta\to\alpha∀α.∀β.α→β→α 合法。单态类型也是量化零个变量的类型方案。

例如 ∀α. α→β\forall\alpha.\,\alpha\to\beta∀α.α→β 中，α\alphaα 是约束变量，β\betaβ 是自由类型变量。使用该方案时可独立实例化 α\alphaα；β\betaβ 没有被量化，仍与外部共享同一个类型约束，不能在每次使用时任意另选。

自由类型变量 ftv 的归纳定义

ftv⁡\operatorname{ftv}ftv（free type variables）返回类型或类型方案中自由出现的类型变量集合。对基础类型 ι\iotaι（如 Int、Bool），定义为：

ftv⁡(α)={α},ftv⁡(ι)=∅,ftv⁡(τ1→τ2)=ftv⁡(τ1)∪ftv⁡(τ2),ftv⁡(∀α.σ)=ftv⁡(σ)∖{α}.\begin{aligned} \operatorname{ftv}(\alpha)&=\{\alpha\},\\ \operatorname{ftv}(\iota)&=\varnothing,\\ \operatorname{ftv}(\tau_1\to\tau_2)&=\operatorname{ftv}(\tau_1)\cup\operatorname{ftv}(\tau_2),\\ \operatorname{ftv}(\forall\alpha.\sigma)&=\operatorname{ftv}(\sigma)\setminus\{\alpha\}. \end{aligned} ftv(α)ftv(ι)ftv(τ1​→τ2​)ftv(∀α.σ)​={α},=∅,=ftv(τ1​)∪ftv(τ2​),=ftv(σ)∖{α}.​

这是按语法结构递归计算的定义：遇到类型变量就收集它，基础类型没有自由类型变量，函数类型合并两侧的集合，全称量词则移除它绑定的变量。例如：

ftv⁡(∀α.α→β)=({α}∪{β})∖{α}={β}.\operatorname{ftv}(\forall\alpha.\alpha\to\beta) =(\{\alpha\}\cup\{\beta\})\setminus\{\alpha\} =\{\beta\}. ftv(∀α.α→β)=({α}∪{β})∖{α}={β}.

环境的自由类型变量是各绑定方案的自由类型变量的并集：

ftv⁡(Γ)=⋃x:σ∈Γftv⁡(σ).\operatorname{ftv}(\Gamma) =\bigcup_{x:\sigma\in\Gamma}\operatorname{ftv}(\sigma). ftv(Γ)=x:σ∈Γ⋃​ftv(σ).

替换与实例化

类型替换与复合

类型替换是类型变量到单态类型的有限映射，未列出的变量保持不变：

S=[α1↦τ1,…,αn↦τn].S=[\alpha_1\mapsto\tau_1,\ldots,\alpha_n\mapsto\tau_n]. S=[α1​↦τ1​,…,αn​↦τn​].

替换按类型结构递归作用：基础类型保持不变，函数类型的两侧分别替换。

Sι=ι,S(τ1→τ2)=Sτ1→Sτ2.S\iota=\iota,\qquad S(\tau_1\to\tau_2)=S\tau_1\to S\tau_2. Sι=ι,S(τ1​→τ2​)=Sτ1​→Sτ2​.

例如 S=[α↦Int]S=[\alpha\mapsto\mathrm{Int}]S=[α↦Int]，则 S(α→α)=Int→IntS(\alpha\to\alpha)=\mathrm{Int}\to\mathrm{Int}S(α→α)=Int→Int。

替换的复合从右向左执行：

(S1∘S2)τ=S1(S2τ).(S_1\circ S_2)\tau=S_1(S_2\tau). (S1​∘S2​)τ=S1​(S2​τ).

例如 S2=[α↦β]S_2=[\alpha\mapsto\beta]S2​=[α↦β]、S1=[β↦Int]S_1=[\beta\mapsto\mathrm{Int}]S1​=[β↦Int]，先用 S2S_2S2​，再用 S1S_1S1​，得到 (S1∘S2)(α→α)=Int→Int(S_1\circ S_2)(\alpha\to\alpha)=\mathrm{Int}\to\mathrm{Int}(S1​∘S2​)(α→α)=Int→Int。

替换作用于类型方案时，只替换自由出现的变量；必要时先对量词绑定的变量换名（α 变换），避免变量捕获。

实例化关系与一般性

设 σ=∀α1⋯αn.τ\sigma=\forall\alpha_1\cdots\alpha_n.\tauσ=∀α1​⋯αn​.τ。若存在单态类型 τ1,…,τn\tau_1,\ldots,\tau_nτ1​,…,τn​，使得

τ′=[α1↦τ1,…,αn↦τn]τ,\tau'=[\alpha_1\mapsto\tau_1,\ldots,\alpha_n\mapsto\tau_n]\tau, τ′=[α1​↦τ1​,…,αn​↦τn​]τ,

则称 τ′\tau'τ′ 是 σ\sigmaσ 的一个实例，记为 σ⊑τ′\sigma\sqsubseteq\tau'σ⊑τ′。左侧比右侧更一般；实例化后可选择的范围缩小或保持不变。实例中的类型变量不必全部变成 Int、Bool 等基础类型，也可以替换为含变量的函数类型。

例如对 σ=∀α.α→α\sigma=\forall\alpha.\alpha\to\alphaσ=∀α.α→α：

为量化变量选择的类型 得到的实例
α↦Int\alpha\mapsto\mathrm{Int}α↦Int Int→Int\mathrm{Int}\to\mathrm{Int}Int→Int
α↦β→β\alpha\mapsto\beta\to\betaα↦β→β (β→β)→(β→β)(\beta\to\beta)\to(\beta\to\beta)(β→β)→(β→β)

反向不成立：Int→Int⋢∀α.α→α\mathrm{Int}\to\mathrm{Int}\not\sqsubseteq\forall\alpha.\alpha\to\alphaInt→Int⊑∀α.α→α。实例化不能把具体的 Int 重新变成“任意类型”；引入全称量词需要泛化，并满足环境中自由类型变量的限制。

实例化与普通替换的区别

类型方案 ∀α.α→β\forall\alpha.\alpha\to\beta∀α.α→β 承诺：无论选择哪种单态类型作为 α\alphaα，函数都能接受该类型的输入；结果仍是同一个 β\betaβ。因此，实例化可以消去量词，把其作用域中的 α\alphaα 一致替换为选定类型，得到如 Int→β\mathrm{Int}\to\betaInt→β 或 Bool→β\mathrm{Bool}\to\betaBool→β。它没有承诺结果类型也能任意选择。

普通替换 S=[β↦Int]S=[\beta\mapsto\mathrm{Int}]S=[β↦Int] 作用于方案的自由变量：S(∀α.α→β)=∀α.α→IntS(\forall\alpha.\alpha\to\beta)=\forall\alpha.\alpha\to\mathrm{Int}S(∀α.α→β)=∀α.α→Int，保留量词。方案实例化则消去选定的外层量词，并替换其原先绑定的出现。两者都涉及替换，但操作对象和作用不同；实现时需通过换名避免变量捕获。

类型环境与泛化：保留对外部的依赖

类型环境 Γ\GammaΓ 记录当前程序变量的类型方案。例如 Γ={y:β}\Gamma=\{y:\beta\}Γ={y:β} 表示外部变量 y 的类型是尚未确定的 β\betaβ。

fun y ->
  let f = fun x -> y in
  (f 1, f true)

推断 f 的定义时，设 x 的类型为 α\alphaα，则函数类型为 α→β\alpha\to\betaα→β。输入类型没有受外部环境约束，可以在 let 处泛化；输出却来自同一个外部变量 y，必须保留与它的联系。因此 f 的方案为 ∀α. α→β\forall\alpha.\,\alpha\to\beta∀α.α→β。两次调用可分别输入整数与布尔值，但结果类型都是 β\betaβ，整个二元组类型为 β×β\beta\times\betaβ×β。

泛化把待泛化类型中、不在当前环境中自由出现的类型变量加上全称量词：

gen⁡(Γ,τ)=∀αˉ. τ,αˉ=ftv⁡(τ)∖ftv⁡(Γ).\operatorname{gen}(\Gamma,\tau) =\forall\bar\alpha.\,\tau, \qquad \bar\alpha=\operatorname{ftv}(\tau)\setminus\operatorname{ftv}(\Gamma). gen(Γ,τ)=∀αˉ.τ,αˉ=ftv(τ)∖ftv(Γ).

判断能否泛化时，看变量是否在环境中自由出现，而非是否出现过同名字母；量词绑定的变量可换名。

泛化建立可复用的类型方案；实例化则在使用处为方案中量化的变量选择单态类型。把外部仍在共享的自由变量量化，会错误地允许各使用处脱离外部约束。

类型判断与函数的基本规则

Γ⊢e:σ\Gamma\vdash e:\sigmaΓ⊢e:σ 表示“在类型环境 Γ\GammaΓ 下，表达式 eee 具有类型方案 σ\sigmaσ”。这是静态类型判断，不表示执行 eee。推理规则横线上方是前提，下方是结论；只有全部前提成立，才能使用该规则得到结论。

语法上，fun x -> e 对应 λx.e\lambda x.eλx.e：接收参数 x，计算函数体 e。代码中的 -> 分隔参数与函数体，类型中的 →\to→ 则连接输入与输出类型。例如 fun f -> fun x -> f x 对应 λf.λx.f x\lambda f.\lambda x.f\,xλf.λx.fx，先接收 f，返回一个等待 x 的函数。

Var：变量查环境

x : σ ∈ Γ
─────────── Var
Γ ⊢ x : σ

环境里存储的是类型方案，查出后若要使用其单态实例，还需 Inst 规则；Var 本身不负责实例化。

Abs：假设参数类型，推导函数体

Γ, x : τ₁ ⊢ e : τ₂
──────────────────── Abs
Γ ⊢ λx.e : τ₁ → τ₂

先把参数 x 的单态类型加入环境，推导函数体类型，再组成函数类型。同一作用域内该参数的各次使用共享同一个单态类型约束。

App：函数输入类型与实参类型相同

Γ ⊢ e₁ : τ₁ → τ₂    Γ ⊢ e₂ : τ₁
───────────────────────────────── App
Γ ⊢ e₁ e₂ : τ₂

应用 e₁ e₂ 要求 e₁ 是函数，并且其输入类型与 e₂ 的类型相同，结果为函数的输出类型。类型未知时，这个相等要求形成约束，之后由合一求解；规则本身说明什么类型判断合法。

例如恒等函数的推导为：

x : α ∈ {x : α}
───────────────── Var
{x : α} ⊢ x : α
───────────────── Abs
∅ ⊢ λx.x : α → α

从目标向上寻找所需前提，再从已成立的前提向下得到结论。若要进一步得到 ∀α.α→α\forall\alpha.\alpha\to\alpha∀α.α→α，还需 Gen 规则，Abs 本身不添加全称量词。

对 λf.λx.f x\lambda f.\lambda x.f\,xλf.λx.fx，设 x:αx:\alphax:α、应用结果为 β\betaβ，由 App 要求 f:α→βf:\alpha\to\betaf:α→β。内层函数类型为 α→β\alpha\to\betaα→β，外层以这个类型的 f 为输入，返回内层函数，故整个类型为 (α→β)→(α→β)(\alpha\to\beta)\to(\alpha\to\beta)(α→β)→(α→β)。

Let、Gen 与 Inst：多态的建立和使用

以下是把泛化与实例化分开的声明式规则；它们规定哪些判断合法。算法 W 则采用固定策略：在 let 处泛化，在变量使用处实例化。

Let：绑定定义的类型方案

Γ ⊢ e₁ : σ₁    Γ, x : σ₁ ⊢ e₂ : σ₂
──────────────────────────────────── Let
Γ ⊢ let x = e₁ in e₂ : σ₂

let x = e₁ in e₂ 中，e₁ 是定义，e₂ 是名字 x 的使用范围。规则有两个前提：

  1. 在原环境 Γ\GammaΓ 中，推导定义 e1e_1e1​ 的类型方案 σ1\sigma_1σ1​。
  2. 在加入绑定 x:σ1x:\sigma_1x:σ1​ 的环境中，推导使用部分 e2e_2e2​ 的类型 σ2\sigma_2σ2​。

结论是：整个 let 表达式的类型为 σ2\sigma_2σ2​，即使用部分的类型。这里是静态地扩展类型环境，不是执行定义或存储运行时值。

Let 本身不添加量词。 它允许把已经得到的类型方案绑定给名字；定义是否具有多态类型、哪些变量可以量化，需要由 Gen 及其附加条件决定。

Gen：在不破坏环境依赖时引入量词

Γ ⊢ e : σ    α ∉ ftv(Γ)
──────────────────────── Gen
Γ ⊢ e : ∀α.σ

前提是表达式 eee 已有类型 σ\sigmaσ，并且待量化变量 α\alphaα 不在当前环境中自由出现。结论是在类型外层添加 ∀α\forall\alpha∀α：该表达式可以对任意选择的 α\alphaα 成立。表达式和环境都不改变。

附加条件保证被量化的变量不与外部绑定共享类型约束。若 α∈ftv⁡(Γ)\alpha\in\operatorname{ftv}(\Gamma)α∈ftv(Γ)，外部仍依赖这个未知类型，就不能把它变成各使用处可独立选择的变量。连续应用 Gen，可以量化多个满足条件的变量；gen⁡(Γ,τ)\operatorname{gen}(\Gamma,\tau)gen(Γ,τ) 将其中所有可量化的自由变量一起泛化。

Gen 不会改变 Abs 的参数规则：Abs 引入的参数仍是单态类型；泛化整个函数表达式的类型，并不等于把其参数改为多态参数。

Inst：在使用处取类型方案的实例

Γ ⊢ e : σ    τ 是 σ 的单态实例
────────────────────────────── Inst
Γ ⊢ e : τ

前提是 eee 已有类型方案 σ\sigmaσ，且所选单态类型 τ\tauτ 是它的合法实例（σ⊑τ\sigma\sqsubseteq\tauσ⊑τ）。实例化消去量词，将其绑定变量一致替换为所选单态类型；方案中的自由变量继续共享原有约束。

每次使用可以独立实例化，原环境中的类型方案保持不变。 一次实例化不会把该名字在后续所有位置的类型永久收窄。Var 只从环境查出方案，Inst 才负责选取本次使用的实例；之后 App 检查实例中的函数输入类型与实参是否一致。

三条规则如何配合

推导 let x = e₁ in e₂ 时，通常先推导定义的单态类型，再用 Gen 量化不与环境共享的变量，以 Let 将所得方案绑定给 x；推导 e₂ 时，每次使用 x 都由 Var 查出方案，再由 Inst 选取本次需要的实例。

Gen 建立一般性，Let 将方案与名字关联，Inst 使用方案允许的具体选择。声明式规则允许 Gen、Inst 在满足前提的位置使用；算法 W 则用固定的泛化、实例化位置实现类型推断。

算法 W：用约束计算类型

从声明式规则到固定推断策略

声明式规则允许在满足条件的位置使用 Gen、Inst，Abs 也未指定如何选择参数类型。算法 W 消除这些选择：根据表达式语法选取分支，在变量使用处实例化、在 let 处泛化；为尚未知的类型生成全新类型变量，随后通过应用等关系产生约束，用合一求解。

“全新”表示该变量与已有未知数没有任何预先共享的关系。只有后续约束要求相等时，才将它们联系起来，避免过早限制类型的一般性。

输入与输出：为什么同时返回替换和类型

W(Γ,e)=(S,τ),SΓ⊢e:τ.W(\Gamma,e)=(S,\tau),\qquad S\Gamma\vdash e:\tau. W(Γ,e)=(S,τ),SΓ⊢e:τ.

  • Γ\GammaΓ：推断开始时的类型环境。
  • eee：待推断的表达式。
  • SSS：推断中求得的类型替换，记录对已有未知类型的约束。
  • τ\tauτ：表达式的推断结果，是单态类型，可以仍含类型变量。

SΓS\GammaSΓ 表示将替换应用到环境中各方案的自由类型变量，保留量词绑定的变量。返回 SSS 是为了让后续推断共享已求得的约束；只返回 τ\tauτ 会丢失对环境的更新。这里返回的 τ\tauτ 已按本次推断的替换更新，不需要按定义再额外作用一次 SSS。

W 的输出不一定是 Int、Bool 等完全具体的类型，也不直接把所有剩余变量加上量词。let 分支在更新后的环境中调用泛化；对闭合表达式，最终也可对结果类型泛化，得到主类型方案。

合一的任务

应用要求函数类型与“实参类型 →\to→ 结果类型”相同。若类型尚未知，就求替换 UUU 使两侧相等：Uτ1=Uτ2U\tau_1=U\tau_2Uτ1​=Uτ2​。合一选择满足等式的最一般替换，保留约束未要求确定的变量；类型结构冲突时报告失败。

最一般合一子与递归求解

若替换 SSS 满足 Sτ1=Sτ2S\tau_1=S\tau_2Sτ1​=Sτ2​，则称其为 τ1\tau_1τ1​、τ2\tau_2τ2​ 的合一子。最一般合一子（most general unifier，mgu）UUU 还要求：其他任何合一子 SSS 都能通过继续替换 UUU 得到，即存在 RRR 使 S=R∘US=R\circ US=R∘U（比较相关类型变量上的作用）。因此，合一不额外指定等式未要求确定的类型。

合一处理的是单态类型；类型方案先实例化，再参与这里的求解。[][][] 表示恒等替换，以下分支按顺序匹配：

unify(α, α) = []

unify(α, τ) =
  if α ∈ ftv(τ) then fail
  else [α ↦ τ]

unify(τ, α) = unify(α, τ)
unify(ι, ι) = []

unify(τ₁ → τ₂, τ₁′ → τ₂′) =
  S₁ = unify(τ₁, τ₁′)
  S₂ = unify(S₁τ₂, S₁τ₂′)
  return S₂ ∘ S₁

unify(_, _) = fail

相同类型不需要更新；类型变量可以替换为不包含自身的类型；两个函数类型则先合一输入，再把所得替换应用到输出类型上继续合一。最后返回先执行 S1S_1S1​、再执行 S2S_2S2​ 的复合替换。输入与输出可能共享类型变量，所以不能忽略第一步的结果而独立求解第二步。

不同基础类型之间，以及基础类型与函数类型之间，均不能合一。变量与自身相等应先直接成功，不能落入后续的发生检查而被误判。

发生检查：排除无限类型

在非平凡的变量绑定 α↦τ\alpha\mapsto\tauα↦τ 前，检查 α∉ftv⁡(τ)\alpha\notin\operatorname{ftv}(\tau)α∈/ftv(τ)，称为发生检查（occurs check）。若待绑定类型内部包含该变量自身，反复展开将需要无限嵌套的类型结构，无法用 HM 的有限类型语法表示，因此合一失败。这是对求解结果的结构限制，与 Int、Bool 等基础类型冲突是不同的失败原因。

W 的变量分支：查方案，生成新实例

W(Γ, x):
  取 Γ(x) = ∀α₁…αₙ.τ
  生成互不相同、且未使用过的类型变量 β₁,…,βₙ
  返回 ([], [α₁↦β₁,…,αₙ↦βₙ]τ)

这一分支合并了 Var 与 Inst：只把方案中量化的变量换成全新变量，保留其自由变量的共享关系。每次使用独立生成新变量，避免多态名字的不同使用处被错误地绑定在一起；同一次实例化中，同一个量化变量的所有出现仍一致替换。

为什么每次实例化必须换新变量？

环境里是：

𝑘:∀𝛼.𝛼→𝛽

它允许每次使用独立选择输入类型，因此两次查找应当返回：

第一次：([], δ₁ → β)
第二次：([], δ₂ → β)

这里 δ₁、δ₂ 是不同的未知数；β 始终共享。

想象后面分别调用：

(k 1, k true)

第一次要求 δ₁ = Int，第二次要求 δ₂ = Bool，可以同时成立。

返回的替换为恒等替换 [][][]：实例化创建本次使用的类型，不改变原环境中的自由类型变量，也没有新增等式需要求解。实例化用到的替换作用于量词去掉后的类型主体，不作为对原环境的更新返回。若方案没有量化变量，就直接返回其原有单态类型；未绑定的变量则查找失败。

W 的抽象分支：递归推导，再更新参数类型

W(Γ, λx.e):
  生成全新类型变量 β
  (S₁, τ₁) = W(Γ[x ↦ β], e)
  返回 (S₁, S₁β → τ₁)

Γ[x↦β]\Gamma[x\mapsto\beta]Γ[x↦β] 表示在函数体的环境中将参数 x 绑定为单态类型 β\betaβ，遮蔽原有同名绑定。它是类型环境的扩展，与类型变量替换 S1S_1S1​ 不同。

函数体的推导可能确定或收窄参数类型，所以返回时必须使用 S1βS_1\betaS1​β，不能仍把参数类型写成未经更新的 β\betaβ。函数体返回的 τ1\tau_1τ1​ 已反映本次递归推断求得的约束，直接作为输出类型；S1S_1S1​ 同时向外返回，使外部共享的类型变量也获得更新。

该分支不泛化参数，也不直接给整个函数结果添加量词。参数在函数体中保持单态；将来若在 let 处绑定整个函数，再按环境条件泛化其类型。

W 的应用分支：两次递归，一次合一

W(Γ, e₁ e₂):
  (S₁, τ₁) = W(Γ, e₁)
  (S₂, τ₂) = W(S₁Γ, e₂)
  生成全新类型变量 β
  U = unify(S₂τ₁, τ₂ → β)
  返回 (U ∘ S₂ ∘ S₁, Uβ)

e₁ 是函数位置的表达式，e₂ 是实参表达式。四步分别完成函数推断、实参推断、类型匹配和结果回传；这些是类型推断的处理顺序，不表示程序运行时必须采用相同求值顺序。

  1. 先推函数，得到函数位置表达式的类型 τ1\tau_1τ1​ 与替换 S1S_1S1​。此时 τ1\tau_1τ1​ 可能仍是未知类型，尚未确定为箭头结构。
  2. 带着已知约束推实参：使用环境 S1ΓS_1\GammaS1​Γ。函数与实参可能引用共享的环境变量，推函数时得到的信息必须传入实参推断。
  3. 合一函数类型与调用要求：实参类型为 τ2\tau_2τ2​，结果暂设为全新 β\betaβ，所以函数必须符合 τ2→β\tau_2\to\betaτ2​→β。实参推断可能进一步确定 τ1\tau_1τ1​ 中共享的变量，故合一前先更新为 S2τ1S_2\tau_1S2​τ1​。τ2\tau_2τ2​ 已是第二次递归的结果类型，无需再重复施加 S2S_2S2​。
  4. 回传全部约束和调用结果：替换按产生顺序先 S1S_1S1​、再 S2S_2S2​、最后 UUU，因此写成 U∘S2∘S1U\circ S_2\circ S_1U∘S2​∘S1​；结果为 UβU\betaUβ。β\betaβ 在两次递归后才生成，先前替换不会作用于它。

最终替换的含义是 (U∘S2∘S1)τ=U(S2(S1τ))(U\circ S_2\circ S_1)\tau=U(S_2(S_1\tau))(U∘S2​∘S1​)τ=U(S2​(S1​τ))。替换复合不是简单拼接映射：后续替换还需更新前面映射所指向的类型。若合一失败，则这次应用无法类型化，W 报告失败。

id 3：实例化后成功应用

设 Γ(id)=∀α.α→α\Gamma(id)=\forall\alpha.\alpha\to\alphaΓ(id)=∀α.α→α。

① 推函数：W(Γ, id) = ([], β₁ → β₁)
② 推实参：W(Γ, 3)  = ([], Int)
③ 新建结果变量 β₂，合一：
   β₁ → β₁ = Int → β₂
   U = [β₁ ↦ Int, β₂ ↦ Int]
④ 返回：(U, Uβ₂) = (U, Int)

两次递归的替换均为恒等替换，最终替换只剩 UUU。它约束本次实例化的新变量，不改变环境中 id 的多态方案。

f x：将未知类型确定为函数类型

设 Γ={f:β1,x:β2}\Gamma=\{f:\beta_1,x:\beta_2\}Γ={f:β1​,x:β2​}，两者均为单态绑定。

① 推函数：W(Γ, f) = ([], β₁)
② 推实参：W(Γ, x) = ([], β₂)
③ 新建结果变量 β₃，合一：
   β₁ = β₂ → β₃
   U = [β₁ ↦ β₂ → β₃]
④ 返回：(U, β₃)

开始时不必预先知道 f 是函数；应用产生的约束会确定其箭头结构。更新后的环境为 UΓ={f:β2→β3,x:β2}U\Gamma=\{f:\beta_2\to\beta_3,x:\beta_2\}UΓ={f:β2​→β3​,x:β2​}，但输入和结果仍可保持未知。

1 2：函数位置不是函数，合一失败

① 推函数位置：W(Γ, 1) = ([], Int)
② 推实参：    W(Γ, 2) = ([], Int)
③ 新建结果变量 β，尝试合一：
   Int = Int → β
   基础类型与函数类型的结构不同，失败。

语法允许写出应用形式，不意味着函数位置的表达式一定具有函数类型。W 在第三步发现冲突，不返回成功的类型结果。

λf.λx.f x：将应用中求得的替换回传给外层

先为参数假设 f:β1f:\beta_1f:β1​、x:β2x:\beta_2x:β2​。内层 f x 的推断与上一成功例相同：

W({f:β₁, x:β₂}, f x)
  = (U, β₃)，其中 U = [β₁ ↦ β₂ → β₃]

随后逐层使用抽象分支组装类型：

内层 λx.f x：
  返回 (U, Uβ₂ → β₃)
     = (U, β₂ → β₃)

外层 λf.λx.f x：
  返回 (U, Uβ₁ → (β₂ → β₃))
     = (U, (β₂ → β₃) → (β₂ → β₃))

应用中发现 f 必须具有 β2→β3\beta_2\to\beta_3β2​→β3​ 类型，这个约束必须通过返回的 UUU 传回外层。若外层仍使用最初的 β1\beta_1β1​，就会漏掉参数 f 与内层函数类型之间的联系。

本例具体展示的是应用的替换回传，以及抽象分支对参数类型的更新；内层应用的 S1,S2S_1,S_2S1​,S2​ 均为恒等替换，因此它本身没有展示非空 S2S_2S2​ 更新 τ1\tau_1τ1​ 的过程。

W 的 let 分支：更新环境后泛化

W(Γ, let x = e₁ in e₂):
  (S₁, τ₁) = W(Γ, e₁)
  σ = gen(S₁Γ, τ₁)
  (S₂, τ₂) = W((S₁Γ)[x ↦ σ], e₂)
  返回 (S₂ ∘ S₁, τ₂)

此处讨论非递归 let：先在原环境中推定义 e1e_1e1​，此时尚未加入新绑定 x。得到的 τ1\tau_1τ1​ 已反映本次推断约束；S1S_1S1​ 则用于更新外部环境。

必须相对于更新后的环境 S1ΓS_1\GammaS1​Γ 泛化：

σ=gen⁡(S1Γ,τ1)=∀αˉ.τ1,αˉ=ftv⁡(τ1)∖ftv⁡(S1Γ).\sigma=\operatorname{gen}(S_1\Gamma,\tau_1) =\forall\bar\alpha.\tau_1, \qquad \bar\alpha=\operatorname{ftv}(\tau_1)\setminus\operatorname{ftv}(S_1\Gamma). σ=gen(S1​Γ,τ1​)=∀αˉ.τ1​,αˉ=ftv(τ1​)∖ftv(S1​Γ).

推定义时可能发现其类型变量与外部变量共享。若仍检查旧环境 Γ\GammaΓ，会遗漏这些新建立的联系，错误地量化本应共享的变量。若没有可量化的变量，σ\sigmaσ 就是原来的单态类型，let 不会凭空制造多态。

随后将 x 的方案加入更新后的环境，递归推使用部分 e2e_2e2​。每次使用 x 时，变量分支独立实例化方案的量化变量；方案中的自由变量继续共享。不同使用处可以有不同输入类型，而共享的结果类型变量仍保持一致，两者不冲突。

整个表达式的类型是使用部分返回的 τ2\tau_2τ2​，并非定义类型 τ1\tau_1τ1​。总替换按推断顺序先施加 S1S_1S1​、再施加 S2S_2S2​，故返回 S2∘S1S_2\circ S_1S2​∘S1​。τ2\tau_2τ2​ 已是第二次递归的结果类型，无需再施加一次 S2S_2S2​。该分支没有额外的应用匹配要求，因此不像 App 分支那样再执行一次合一；递归推断内部仍可能发生合一。

四个分支的整体配合

表达式形状 分支的职责 信息如何保留
变量 x 查方案，将量化变量实例化为全新变量 自由变量仍共享，返回恒等替换
抽象 λx.e 给参数一个新单态未知数，递归推函数体 用函数体返回的替换更新参数类型
应用 e₁ e₂ 依次推函数、实参，再合一调用要求 更新环境与函数类型，按顺序复合三段替换
let x = e₁ in e₂ 推定义，相对于更新后的环境泛化，再推使用部分 方案绑定给名字，复合两次递归的替换

处理嵌套表达式时，每次按当前最外层语法选择分支：向内递归时传入已更新的环境，向外返回时更新相关类型并复合替换。W(Γ,e)=(S,τ)W(\Gamma,e)=(S,\tau)W(Γ,e)=(S,τ) 中，τ\tauτ 描述当前表达式的类型，SSS 保存需传给其他相关位置的约束。

实例化、合一与泛化分别承担不同方向的工作：实例化把方案变成本次使用的新实例；合一求解类型之间必须相等的约束；泛化将不与环境共享的未知数量化，建立可复用的方案。新变量用于推迟决定，合一只作必要限制，替换则保证相关位置共享求解结果。

算法正确性：可靠性、完备性与主类型

以下结论针对前述 HM 核心语言与类型规则。

可靠性（soundness）：W 成功返回的结果一定能由类型规则证明：

W(Γ,e)=(S,τ)⟹SΓ⊢e:τ.W(\Gamma,e)=(S,\tau) \quad\Longrightarrow\quad S\Gamma\vdash e:\tau. W(Γ,e)=(S,τ)⟹SΓ⊢e:τ.

它保证算法不会给出非法类型；这里的“可靠性”是算法结果相对于类型规则的正确性。良类型程序的运行时安全，还需类型系统相对于运行语义的安全性论证。

完备性（completeness）：如果表达式在给定环境的某个类型替换下可以按规则类型化，W 就能成功找到结果，不会漏掉规则允许的表达式。其结果保留最一般的约束，其他合法结果可以在此基础上进一步实例化得到；开放表达式须同时考虑环境与表达式类型中的共享变量。

主类型性质：对闭合表达式，若 W(∅,e)=(S,τ)W(\varnothing,e)=(S,\tau)W(∅,e)=(S,τ)，则 gen⁡(∅,τ)\operatorname{gen}(\varnothing,\tau)gen(∅,τ) 给出主类型方案，其他合法单态类型都是它的实例。W 不仅找到一个可用类型，还保留所有不必预先确定的类型选择。

W 在有限步内返回结果或报告失败，结合可靠性与完备性，使 HM 核心语言的可类型化性可判定。

特性与设计哲学

5.1 四个特点如何联系起来

特点 含义与作用
let 多态 W 在 let 处按环境条件泛化，使用处各自实例化；λ 参数保持单态
主类型 保留所有合法的实例化选择，避免仅为某次使用而过早确定类型；主类型方案在量化变量换名的意义下唯一
全自动且可判定的推断 对 HM 核心语言，可以不写类型标注，W 在有限步内给出最一般的推断结果或报告失败；可判定不等于最坏情况下总是高效
可组合性 根据定义本身和环境推断类型，再通过类型方案检查各使用处；无需复制定义、为每次调用重新推导其函数体

这四点共同支持库函数复用：定义处建立尽可能一般的方案，使用处根据调用要求实例化，再用合一检查组合。可组合性仍依赖环境中已知的类型与共享约束，不意味着任意开放定义都能脱离上下文独立推断；它为模块化提供基础，但不单独保证语言的完整分离编译机制。

为什么限制多态的位置

HM 选择在有限的多态表达力下保留全自动推断和主类型性质。

let 绑定与 λ 参数承担不同职责。 推断 let 定义后，算法可检查其类型与环境的依赖，再泛化不共享的变量。λ 参数没有可先分析的定义体，W 先给它一个单态未知数，由函数体约束其类型；每次使用不能独立实例化这个未知数。let 的定义可以引用外部变量，类型也可以仍含未知数，并非必须封闭或完全具体后才泛化。

外层量词与多态参数不同。 ∀α.(α→α)→Int\forall\alpha.(\alpha\to\alpha)\to\mathrm{Int}∀α.(α→α)→Int 允许每次使用整个方案时选择一个 α\alphaα，但函数体内的参数仍只有一个单态函数类型。(∀α.α→α)→Int(\forall\alpha.\alpha\to\alpha)\to\mathrm{Int}(∀α.α→α)→Int 则要求实参本身具有多态方案，函数体可在不同类型上使用它；这种量词出现在函数输入内部的类型超出 HM。

前束量词让 W 在变量处实例化后，使用单态类型的一阶合一求解约束。放宽到多态参数、高秩类型时，不能直接沿用 W 的全自动推断保证，常需额外标注和不同的检查算法。不能笼统断言任何高秩扩展都不可判定，或所有 λ 参数多态都会破坏安全性；具体结论取决于允许的类型与推断任务。

主类型使推断结果具有可预测的一般性。 其他合法类型可由主类型实例化得到，无需针对使用场景选择多个互不相容的候选类型方案。HM 以限制表达力换取这种自动化；受控扩展可以用显式类型标注等机制增加表达力。

可变状态、递归与表达力的边界

值限制（value restriction）：加入可变引用后，不能仅凭环境自由变量条件就泛化任意 let 定义。不同类型的使用处若共享同一个可写存储位置，可能先按一种类型写入、再按另一种类型读取，破坏类型安全。经典值限制保守地将泛化限制在语法值等非扩张表达式上；OCaml 的宽松值限制还允许按协变性泛化部分变量。这里需记住的是：带可变状态的语言必须增加泛化条件，不能直接照搬纯 HM 的 let 分支。

多态递归（polymorphic recursion）：指函数在自身的定义内部，以不同类型实例递归调用自己；与定义完成后从外部用不同类型调用它不同。通常的 ML 式递归推断在递归定义内部先给函数一个共享的单态类型，完成推断后再泛化。一般的多态递归不能保持无标注的完备自动推断，需要适当的显式多态标注等机制支持。

表达力边界：前述 HM 核心不包含子类型、重载、高秩或存在类型。现实语言可以通过额外机制扩展这些能力，但扩展后的规则、标注需求与推断保证需要分别说明，不能直接继承核心 W 的全部结论。

局限与代价

错误位置不一定是根因。 合一在冲突出现的位置失败，但真正写错的可能是更早的定义、参数顺序或类型假设。自动推断减少标注，也可能让约束的来源更难追踪；适当的接口标注有助于定位预期与实际类型的差异。

表达力受限。 HM 核心不直接支持重载、子类型、高秩与存在类型等能力；一般的多态递归也超出其无标注推断范围。加入扩展后，需要重新说明规则、标注要求以及主类型和推断保证。

可判定不等于最坏情况下高效。 Mairson 的结果表明，ML 可类型化性判定是确定性指数时间完全的（DEXPTIME-complete）；还存在主类型显式展开后随程序规模指数增长的构造。因此不能把 W 概括为有普遍的线性时间保证。课件所说的实践中常较高效，是实践表现的概括，不是对所有输入的复杂度上界。参见 Mairson，POPL 1990。

此外，类型通过定义之间的依赖传播：修改一个定义，可能改变较远使用处的推断类型或引发新冲突。显式接口可帮助稳定边界。
