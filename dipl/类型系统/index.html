类型系统的作用

类型系统由类型定义和类型检查规则组成，用规则约束表达式的组合，防止某些不合法的操作。例如，在只允许整数相加的规则下，3 + 4 合法，3 + true 不合法。

不同类型之间能否运算取决于具体规则，并非一律禁止；规则可能允许混合数值运算或类型转换。

类型信息还帮助读者理解程序，并为编译器优化提供依据。类型系统会限制允许编写的程序；通过类型检查只代表满足该系统检查的约束，不能保证业务逻辑正确。

例如，map : (A -> B) -> List<A> -> List<B> 表示：给定一个把 A 转换为 B 的函数和一个 A 的列表，返回一个 B 的列表。类型说明输入输出的结构，但通常不能保证实现保持列表长度或满足预期功能。

静态与动态类型检查

核心区别是检查发生的时机，以及检查依据的信息。

  • 静态类型检查：在程序运行前，依据代码及类型信息检查表达式是否符合规则。变量没有显式类型标注，也可能通过类型推断完成静态检查。
  • 动态类型检查：在程序运行时，依据实际参与操作的值检查是否合法。同一个变量名可以先后绑定不同类型的值；并不是原来的值变成了另一种类型。

假设加法只接受整数，下面的 Python 代码在执行加法时才遇到类型错误：

x = "hello"
y = x + 1

在要求加法操作数均为整数的静态类型系统中，可以在运行前拒绝这样的表达式。

静态类型系统也可能支持联合类型、类型收窄和混合数值运算。一个程序能否通过检查，取决于系统的具体规则和分析能力。静态／动态类型不能直接等同于编译／解释执行，也不能单凭这一分类断定性能或可靠性。

类型判断与推理规则

⊢ e : T 表示表达式 e 具有类型 T，是一个类型判断，不是给 e 赋值，也不是计算 e 的结果。涉及变量时需要类型环境，后续写作 Γ ⊢ e : T。

推理规则的横线上方列出前提，下方给出结论。所有前提成立，才能按该规则得到结论；没有前提的规则可直接使用，例如 ⊢ true : Bool。

⊢ e1 : Bool       ⊢ e2 : Bool
----------------------------
     ⊢ e1 and e2 : Bool

此规则要求两个操作数都具有布尔类型。规则中的 e1、e2 可以替换为具体表达式，各个前提又可以由其他规则推导，逐步构成类型推导树。

⊢ b : Bool       ⊢ e1 : T       ⊢ e2 : T
----------------------------------------
       ⊢ if b then e1 else e2 : T

这里要求条件为布尔类型、两个分支具有相同类型 T。按这组规则，即使条件是常量 true，也不能跳过对另一分支的检查。不能用这条规则推导出类型，不代表所有其他类型系统也会拒绝该表达式。

引入规则与消除规则

  • 引入规则（Introduction）说明如何构造某种类型的值；
  • 消除规则（Elimination）说明如何使用该类型的值。

Bool 的基本值是 true 和 false，对应无前提的引入规则：

--------------       ---------------
⊢ true : Bool        ⊢ false : Bool

if b then e1 else e2 是 Bool 的消除形式：使用布尔条件 b 选择分支。其类型规则要求 b : Bool，两个分支都具有类型 T，结果具有类型 T。

消除并不是删除值或类型，而是使用该类型提供的信息；结果也不必与被使用的值具有相同类型。例如 if true then 3 else 4 使用 Bool，产生 Int。引入／消除的分类要明确针对哪种类型。

积类型

积类型 A × B 的一个值同时包含一个 A 值和一个 B 值，写成二元组 (a, b)。例如 (3, true) : Int × Bool；两个分量不必同类型，位置有意义。

引入规则通过两个分量构造二元组：

⊢ e1 : A       ⊢ e2 : B
------------------------
⊢ (e1, e2) : A × B

消除规则通过投影取出分量：

⊢ p : A × B           ⊢ p : A × B
-------------         -------------
⊢ fst p : A           ⊢ snd p : B

fst (3, true) 得到整数 3，snd (3, true) 得到布尔值 true。构造时需要两个分量，使用时可以取第一个、第二个或两者。

若 A 有 m 个可能的值，B 有 n 个可能的值，则每个 A 值可以与每个 B 值组合，A × B 有 m × n 个值。例如 Bool × Bool 有 4 个值。多元组是二元组的推广，记录／结构体可以视为带字段标签的元组。

和类型

和类型 A + B 的值是带标签的选择：或者包含一个 A 值，或者包含一个 B 值。+ 是类型构造符，不是数值加法；不同于积类型，它不要求同时提供两个分量。

约定目标类型为 Int + Bool 时，left 3 表示整数分支，right true 表示布尔分支。标签区分分支，即使两边类型相同也不能省去：在 Bool + Bool 中，left true 和 right true 是不同的值。

引入规则选择一个分支构造值。以下 left/right 都指定以 A + B 为目标类型：

⊢ a : A                 ⊢ b : B
----------------        ----------------
⊢ left a : A + B        ⊢ right b : A + B

消除通过 case／模式匹配区分标签、取出对应分支的值，再执行该分支的处理。完整处理一个 A + B 值必须为两种情况准备处理逻辑，并使两个分支返回同一种结果类型 T。

⊢ e : A + B       ⊢ f : A -> T       ⊢ g : B -> T
-------------------------------------------------
              ⊢ case e do f g : T

若 A 有 m 个值、B 有 n 个值，则带标签的 A + B 有 m + n 个值。例如 Bool + Bool 有 left true、left false、right true、right false 四个值。

Unit 与 Nothing

Unit 恰好有一个值，通常写为 ()，可理解为空元组。它表示操作正常完成，但不携带额外的结果信息。例如输出操作可以具有 String -> Unit 类型。

Nothing 没有任何值，可理解为零个分支的和类型。返回类型为 Nothing 的函数不能正常返回一个结果，例如一直循环或终止执行的函数。Nothing 不等于 null 或 None：后两者是值／构造形式，Nothing 没有值。

T × Unit    ≅ T
T + Nothing ≅ T

第一式中 (t, ()) 与 t 可以相互转换，Unit 分量不增加选择；第二式只能构造 left t，因为不可能提供 Nothing 值构造右分支。这里的等价是可建立相互可逆的转换，不表示类型写法或值的表示完全相同。

若 T 有 n 个值，以上两式对应 n × 1 = n 和 n + 0 = n。Unit 是积类型的单位元，Nothing 是和类型的单位元。

具体表示仍须保留结构：Bool × Unit 的值是 (true, ()) 与 (false, ())；Bool + Nothing 的值是 left true 与 left false，而不是裸的 true、false。

函数类型与类型环境

类型环境与函数调用

类型环境 Γ 记录当前可用变量的类型，不记录它们运行时的具体值。例如 Γ = {x : Int, f : Int -> Bool}。

Γ ⊢ e : T 读作“在类型环境 Γ 下，表达式 e 具有类型 T”。变量的类型通过环境查找得到，例如上述环境下有 Γ ⊢ x : Int。

函数类型 A -> B 表示参数类型为 A、正常返回的结果类型为 B。函数调用是函数类型的消除形式：

Γ ⊢ f : A -> B       Γ ⊢ e : A
------------------------------
         Γ ⊢ f(e) : B

例如 f : Int -> Bool、x : Int 时，f(x) : Bool。这个判断说明返回结果的类型，不能确定具体返回 true 还是 false。在这组简单规则下，f(true) 不满足参数类型要求。

函数定义：引入规则

λx : A. e 表示一个参数 x 类型为 A、函数体为 e 的匿名函数。检查函数体时，将参数绑定 x : A 加入当前类型环境；如果函数体类型为 B，则函数类型为 A -> B。

Γ, x : A ⊢ e : B
------------------------
Γ ⊢ λx : A. e : A -> B

Γ, x : A 是检查函数体时扩展的环境，参数 x 的绑定只在其作用域内有效，并不因此成为外层可用变量。

例如 λx : Int. x + 1 : Int -> Int，因为在包含 x : Int 的环境中，整数加法规则给出 x + 1 : Int。λx : Int. true : Int -> Bool 同样合法：函数体可以不使用参数，参数类型与返回类型也不必相同。

函数定义是函数类型的引入，函数调用是函数类型的消除。定义时检查函数体的类型，不需要实际调用函数。

实际用法：带数据的枚举

课件用仓颉枚举表示算术表达式：

enum Expr =
  | CONST(Int)
  | ADD(Expr, Expr)
  | MUL(Expr, Expr)

一个 Expr 值选择其中一个分支。CONST、ADD、MUL 是标签／构造器；CONST 携带一个整数，ADD 和 MUL 各携带两个 Expr 值。分支之间是和类型关系，同一分支内部的多个字段是积类型关系，其结构可写作递归类型方程：

Expr ≅ Int + (Expr × Expr) + (Expr × Expr)

例如 ADD(CONST(3), CONST(4)) : Expr 表示加法语法树，构造它并不会自动计算出整数 7。ADD 与 MUL 的载荷类型相同，但标签不同，代表不同运算。

求值函数 eval : Expr -> Int 通过模式匹配消除 Expr：CONST 分支取出整数，ADD／MUL 分支递归求值两个子表达式，再做对应运算。三个分支都返回 Int。

从类型规则到检查程序

check(e, T) 判断表达式 e 是否具有目标类型 T，返回的是检查结果 true／false，而不是 e 的求值结果。涉及变量时，还需传入类型环境 Γ。

检查器按表达式的语法结构选择规则，再递归检查各个前提。以布尔常量、逻辑与及条件表达式为例：

check(true, T)  = (T == Bool)
check(false, T) = (T == Bool)

check(e1 and e2, T) =
  (T == Bool) and check(e1, Bool) and check(e2, Bool)

check(if b then e1 else e2, T) =
  check(b, Bool) and check(e1, T) and check(e2, T)

前提中的“且”表示所有检查条件都必须通过。条件表达式的两个分支都按目标类型 T 检查，不是执行 b 后仅检查被选中的分支。

实现检查器不仅要验证规则的前提，也要确认规则结论的类型与目标类型匹配。

联合类型：放宽可能的值，使用时分情况

联合类型（union，也称并类型）A | B 表示值属于 A 或 B；按集合论直觉，其值集合为 A ∪ B。例如 string | number 接受字符串或数字，"read" | "write" 表示有限的两种选择，string | null 表示可能为空的字符串。

function padLeft(value: string, padding: string | number): string {
  if (typeof padding === "number") {
    return " ".repeat(padding) + value;
  }
  return padding + value;
}

这个签名排除 boolean 等输入，同时要求函数体处理两种情况。使用 any 会放弃相应检查；联合类型保留了“只接受这些可能”的约束。

引入、消除与子类型方向

联合的引入只放宽类型，不需要 left／right 包装：

Γ ⊢ e : A                  Γ ⊢ e : B
----------------           ----------------
Γ ⊢ e : A | B              Γ ⊢ e : A | B

只有 x : string | number 时，不能直接使用 x.length，因为 number 没有这一属性。可以使用所有成员都支持的操作；若操作只适用于其中一类，必须先获得相应的分支信息。

消除规则可用以下示意表示；typecase 表示有可靠类型测试的分情况处理，不是所有语言都提供的具体语法：

Γ ⊢ e : A | B     Γ, x : A ⊢ e1 : C     Γ, y : B ⊢ e2 : C
---------------------------------------------------------
       Γ ⊢ typecase e of { A x => e1; B y => e2 } : C

两种可能都要得到结果类型 C。若成员重叠，还须明确测试顺序及剩余情况；无标签联合不能恢复“这个值最初从哪一边加入”。在支持联合结果的系统中，不同分支的结果也可以放宽到共同的联合类型 C。

写 A ≤ B 表示 A 是 B 的子类型，即 A 的值可用在要求 B 的位置。集合语义下：

A ≤ A | B，B ≤ A | B
A | B ≤ C  当且仅当  A ≤ C 且 B ≤ C

因此联合是 A、B 的最小上界（join）：包含两者，又不额外扩大范围。可能的值越多，对未知值能直接使用的专属能力通常越少。

类型收窄与判别联合

类型收窄（narrowing）利用控制流中的事实，缩小某个程序位置上变量的可能类型。上例中，typeof padding === "number" 为真时 padding 是 number；该分支已经 return，后续代码只能来自字符串情况。

常见守卫有 typeof、instanceof、in 与判别字段。收窄依赖可达路径、赋值和分支合流，不能概括成“离开 if 就必定恢复原类型”。TypeScript 的控制流分析说明给出了提前返回后继续保持收窄的例子。

type Shape =
  | { kind: "circle"; r: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.r ** 2;
    case "rect": return s.w * s.h;
    default: {
      const unreachable: never = s;
      return unreachable;
    }
  }
}

共同的字面量字段 kind 使两个对象分支可区分，这叫判别联合。若以后增加一种 Shape 却没有增加处理分支，默认分支中 s : never 的检查会失败；这里用显式检查表达穷尽性要求，普通 switch 并不总会自动拒绝遗漏。

结果类型同样可以写成 { ok: true; value: T } | { ok: false; error: E }。标签让成功与失败即使携带同类型数据也能区分。有限状态、可空值和接受多种参数形态的 API 都是联合的典型用途；TypeScript 的严格空值检查需要开启 strictNullChecks。

交叉类型：同一个值同时满足多个要求

交叉类型（intersection，也称交类型）A & B 表示同一个值同时属于 A 和 B；集合直觉为 A ∩ B。

type Named = { name: string };
type Aged = { age: number };
type Person = Named & Aged;
const p: Person = { name: "Ada", age: 36 };

p 是一个同时满足两种结构要求的对象。交叉类型本身没有创建两个对象，也没有执行字段合并；若要在运行时合并对象，仍需对象展开等实际操作。

引入、消除与共同能力

Γ ⊢ e : A       Γ ⊢ e : B
-------------------------
       Γ ⊢ e : A & B

Γ ⊢ e : A & B              Γ ⊢ e : A & B
-------------              -------------
Γ ⊢ e : A                  Γ ⊢ e : B

引入的两个前提针对同一个 e；消除把这个值按 A 或 B 使用，不像二元组投影那样取出不同分量。子类型方向与联合对偶：

A & B ≤ A，A & B ≤ B
C ≤ A & B  当且仅当  C ≤ A 且 C ≤ B

交叉是最大下界（meet）。要求越多，符合条件的值越少，但能依赖的能力越多。Java 的 <T extends Serializable & Comparable<T>> 是多重能力上界；不意味着 Java 在任意类型位置都允许自由书写交叉类型。

TypeScript 中 string & number 没有普通值，归约为 never；对象类型则可能同时满足两组字段要求。若同名字段分别要求 string 和 number，该字段就必须同时满足不相容的要求，不能把“交叉”理解为后者覆盖前者。

函数类型的交叉可以描述重载契约，例如 ((x: string) => string) & ((x: number) => number) 要求同一个函数满足两种调用关系。它比 (string | number) -> (string | number) 保留了更多输入输出关联；普通联合签名不能单凭参数类型保证返回的是对应成员。

联合／交叉与和／积：范围和数据结构

类型构造 一个值表达什么 构造与使用 适合的需求
联合（union） 属于 A 或 B 原值进入；用共同操作或守卫收窄 多形态参数、可空值
交叉（intersection） 同时满足 A、B 同一值满足两组要求；可按任一类型使用 能力约束、结构组合、重载
和 A + B 选择一个带标签的分支 left／right 引入；按标签 case 需要保留分支身份的数据
积 A × B 包含两个分量 二元组引入；fst／snd 投影 数据聚合

联合不自动增加来源标签：Bool | Bool = Bool，仍只有 true、false；和类型 Bool + Bool 有四个带标签的值。类似地，A & A = A，而积 A × A 携带两个可独立选择的分量。不能因为都能读成“或／且”，就把两对类型构造互换。

集合语义下，联合与交叉满足幂等、交换、结合和分配律，例如：

A | A = A                         A & A = A
A | B = B | A                     A & B = B & A
A & (B | C) = (A & B) | (A & C)
A | ⊥ = A                         A & ⊤ = A

⊥ 的值集合为空，⊤ 覆盖所有值；TypeScript 中通常用 never、unknown 对应这一直觉，any 会绕开检查，不适合当作普通顶类型参与推理。有限集合还满足 |A ∪ B| = |A| + |B| - |A ∩ B|，不能一般地把联合成员数直接相加。

积／和也有代数性质，但常以同构表达：A × B ≅ B × A 通过交换分量实现，A + B ≅ B + A 通过交换分支标签实现；具体值的表示并不因此相同。积、和是否采用名义类型取决于语言，不能从有构造器就推出“所有积／和都必然是名义类型”。

运行时表示与性能边界

TypeScript 的联合／交叉类型标注会被擦除，不因写了类型就新增包装对象或类型表；源程序里的 typeof、判别字段、switch 和对象构造仍会执行。擦除类型标注的成本与执行这些操作的成本要分开。

和类型常见实现是标签与载荷，载荷区域容纳当前分支，并考虑对齐；也可能装箱或优化掉显式标签。例如 Rust 对若干指定类型保证 Option<T> 与 T 同大小，包括满足文档条件的引用类型，利用空值位模式表示 None。Rust 的表示保证说明，有标签的语义不必要求额外堆分配或额外标签字节。

交叉类型也不必对应多张运行时方法表：TypeScript 会擦除，其他语言的接口、trait、字典或多重继承有各自实现。switch 是否生成跳转表、接口调用是否被内联、装箱是否发生，都依赖实现与程序；不能仅凭类型写法给出固定的速度排序。穷尽性检查、类型推断和某些优化可在擦除前完成，擦除不等于丢失全部编译期优化能力。

Hindley–Milner：从类型检查到类型推断

类型检查验证表达式是否符合给定的类型；类型推断依据表达式的结构、变量的使用方式和已知运算的类型，求出表达式应具有的类型。两者都可以在运行前进行，不需要执行函数。

类型检查：程序 + 给定类型 → 验证是否符合规则
类型推断：程序 + 已知类型规则 → 求出类型，或发现约束冲突

例如，已声明 f : Int -> Int，函数体为 x + 1，检查器验证参数 x 和返回表达式都符合声明。省去声明后，写成 f x = x + 1，推断器也能求出类型：本课件的简化语言规定加法只接受两个 Int，并返回 Int，因此 x 必须是 Int，函数体也是 Int，得到 f : Int -> Int。

类型推断省去的是程序员的部分类型标注，并没有省去类型规则或所有已知类型信息。下面的整数、列表示例采用不含重载的简化 Haskell 子集；形式化 HM 核心则以变量、常量、λ 抽象、应用和非递归 let 为研究对象。

Hindley–Milner 类型推断的目标是求出最一般的类型：只施加程序所必需的限制。后续通过“建立语法树 → 分配类型变量 → 生成约束 → 合一求解 → 得到声明类型”展开；无法满足的类型约束意味着程序在这组规则下存在类型错误。

单态类型、类型方案与自由类型变量

HM 将推断中的单态类型 τ 与可复用定义的类型方案 σ 分开：

e ::= x | c | λx. e | e1 e2 | let x = e1 in e2
τ ::= α | Int | Bool | τ -> τ
σ ::= ∀α1 ... αn. τ                 n 可以为 0

这里“单态”指不含全称量词，不是完全没有类型变量。α -> α 含待确定的变量，但仍是 τ；∀α. α -> α 才是可各次实例化的方案。量词位于最外层，(∀α. α -> α) -> Int 这样的多态参数类型不属于基本 HM。列表、积和递归示例是相应扩展，不是这段核心语法自带的构造。

自由类型变量 ftv 是没有被 ∀ 绑定的类型变量，与表达式中的自由变量不同：

ftv(α) = {α}                       ftv(Int) = ftv(Bool) = ∅
ftv(τ1 -> τ2) = ftv(τ1) ∪ ftv(τ2)
ftv(∀α. σ) = ftv(σ) \ {α}
ftv(Γ) = 所有 Γ(x) 的自由类型变量的并集

ftv(∀α. α -> β) = {β}

HM 环境 Γ 将表达式变量映射到类型方案；λ 参数以量化零个变量的单态方案存入。类型替换 S 将自由类型变量映射到类型，按结构作用：S(τ1 -> τ2) = Sτ1 -> Sτ2。作用到方案时不替换受 ∀ 绑定的变量，并在必要时改名避免捕获。

实例化另有明确动作：取 ∀α. α -> α 的一个实例时，去掉量词并把绑定的 α 一致换为某个类型。算法通常先换成全新变量 β，随后由使用约束决定 β；不同使用换不同的新变量，同一次使用的相同变量仍须一致。

let 泛化：只量化不受环境约束的变量

泛化（generalization，也称推广）把一个推断结果变成可复用方案：

gen(Γ, τ) = ∀α1 ... αn. τ
其中 {α1, ..., αn} = ftv(τ) \ ftv(Γ)

例如空环境下 gen(∅, α -> β) = ∀α β. α -> β；若 Γ = {y : β}，就只能得到 ∀α. α -> β。β 与外部 y 的类型相连，不是每次使用都可独立选择的变量。

let id = λx. x in (id 1, id true)     : Int × Bool
λid. (id 1, id true)                 : 在基本 HM 中不可类型化

前者先将 id 泛化为 ∀α. α -> α，两次使用各自实例化；后者的 λ 参数 id 只有一个共享的单态类型，不能同时要求其输入为 Int 与 Bool。即使 let 内没有量化变量，绑定仍合法，只是没有因此获得多态。

反过来，λy. let f = λx. y in (f 1, f true) 是可类型化的：若 y 的类型为 β，则 f 的方案为 ∀α. α -> β。两次调用的参数可以不同，结果必须都是 β，整个表达式具有 β -> (β × β) 类型。禁止量化 β，并不禁止量化与环境无关的参数类型 α。

泛化条件保护了与外部值的联系。例如 (λy. let z = y in z 0) 1 应被拒绝：z 与 y 共享类型，z 0 要求 y 是函数，外层却传入 Int。若错误地把 z 泛化成 ∀α. α，就可能把实际整数 1 当函数调用。

说明性规则：定义什么推导合法

07 材料用六条规则定义判断。以下环境扩展会遮蔽同名旧绑定；Abs 与 App 中的 τ 均为单态类型，Inst 只实例化方案的量化变量，保留环境中的类型联系。

x : σ ∈ Γ
------------- Var
Γ ⊢ x : σ

Γ, x : τ1 ⊢ e : τ2
------------------------- Abs
Γ ⊢ λx. e : τ1 -> τ2

Γ ⊢ e1 : τ2 -> τ       Γ ⊢ e2 : τ2
---------------------------------- App
          Γ ⊢ e1 e2 : τ

Γ ⊢ e1 : σ       Γ, x : σ ⊢ e2 : τ
---------------------------------- Let
      Γ ⊢ let x = e1 in e2 : τ

Γ ⊢ e : σ       α ∉ ftv(Γ)
--------------------------- Gen
Γ ⊢ e : ∀α. σ

Γ ⊢ e : σ       σ′ 是 σ 的合法实例
-------------------------------- Inst
             Γ ⊢ e : σ′

恒等函数的最小推导为：

   x : α ∈ {x : α}
--------------------- Var
   x : α ⊢ x : α
--------------------- Abs
  ∅ ⊢ λx. x : α -> α       α ∉ ftv(∅)
-------------------------------------- Gen
        ∅ ⊢ λx. x : ∀α. α -> α

说明性规则允许在适当位置使用 Gen／Inst；算法 W 将泛化集中在 let、实例化集中在变量使用处，顶层输出也可再泛化。因此“只有 let 多态”是对绑定方式和算法策略的概括，不是说声明式 Gen 规则只能紧跟 Let。

函数调用生成的约束

类型变量表示尚待确定的类型，不是运行时的程序变量。对于调用 f x，若 f、x、整个调用的类型分别为 α、β、γ，则生成约束：

α = β -> γ

f 必须具有函数类型，参数类型必须等于实参 x 的类型，返回类型就是整个调用表达式的类型。例如 f : Int -> Bool 时，约束 Int -> Bool = β -> γ 要求 β = Int、γ = Bool。若实参已知为 Bool，则会产生 Int = Bool 的冲突。

函数定义生成的约束

对于定义 f x = e（或匿名函数 λx. e），若参数 x 的类型为 β、函数体 e 的类型为 γ，则函数类型为 β -> γ。若用 α 表示 f 的类型，也生成 α = β -> γ。

调用规则连接函数、实参与调用结果；定义规则连接函数、形参与函数体。它们形式相同，但对应不同的语法结构。检查函数体时，参数的各次引用使用其绑定的同一个类型变量。

例如 f x = x + 1，先设 x : β；整数加法要求 β = Int，函数体类型为 Int，因此 f : Int -> Int。而 f x = true 只确定函数体为 Bool，未使用的参数不受额外限制，得到 f : β -> Bool；不能仅因结果为 Bool 就把参数也限定为 Bool。

将中缀运算拆成函数调用

课件将 f x = 2 + x 的函数体解析为 ((+) 2) x。(+) 是加法函数，先接受 2，返回一个等待第二个整数的函数，再接受 x。这里的类型是柯里化形式：

(+) : Int -> (Int -> Int)
(+) 2 : Int -> Int
((+) 2) x : Int       要求 x : Int
f : Int -> Int

函数类型箭头向右结合：A -> B -> C 表示 A -> (B -> C)；函数应用向左结合：h a b 表示 (h a) b。前者的第一个调用返回函数，后者再调用该返回函数。它不同于接受一个二元组参数的 (A × B) -> C。

这样把运算拆成两个应用节点后，每个节点都能使用同一条调用约束“函数类型 = 实参类型 -> 调用结果类型”，无需为中缀加法另造一套调用规则。

合一：求解类型约束

合一（unification）寻找对类型变量的统一替换，使所有类型等式同时成立。同一个类型变量在所有约束中必须一致替换，不能在不同位置各选一种类型。

函数类型的等式按结构拆解：A -> B = C -> D 要求 A = C 且 B = D。变量可以替换为类型，例如 α = Int；不同基本类型如 Int = Bool 无法合一。在这里，合一不做运行时类型转换。

以 f x = ((+) 2) x 为例，用 α 表示 x 的类型、β 表示第一次调用 (+) 2 的类型、γ 表示函数体的类型、δ 表示 f 的类型：

Int -> (Int -> Int) = Int -> β     第一次调用
β = α -> γ                       第二次调用
δ = α -> γ                       函数定义

由第一式：β = Int -> Int
代入第二式：Int -> Int = α -> γ
按结构拆解：α = Int，γ = Int
代入第三式：δ = Int -> Int

这些约束来自已知常量／运算的类型和表达式的语法结构。求解得到 f : Int -> Int，不需要计算 2 + x。若同一个变量又被要求为 Bool，则约束冲突，程序在这组规则下存在类型错误。

合一不仅要找一个解，还要保留不必要收窄的自由度。最一般合一子 U 满足：任何其他合一解 S 都可写成 S = R ∘ U，即在 U 的基础上继续替换即可得到。复合从右向左施加：(S2 ∘ S1)τ = S2(S1τ)；不能一般地当作两张替换表的简单并集。

合一类型变量时还必须做发生检查（occurs check）：除 α = α 直接成功外，若 α 出现在待替换类型内部，就不能令 α ↦ τ。

λx. x x
设 x : α，应用结果 : β
函数位置要求：α = α -> β
α 出现在右侧，无法用有限 HM 类型满足，因此拒绝

这与 let id = λx. x in id id 不同：两处 let 绑定的 id 可独立实例化为 a -> a 与 b -> b，约束只需 a = b -> b，结果为 b -> b，没有自身包含。发生检查针对有限类型的核心系统；若语言另行引入递归类型，需要重新规定规则。

算法 W：把规则变成确定的推断步骤

W(Γ, e) = (S, τ) 同时返回类型 τ 与替换 S，保证 SΓ ⊢ e : τ。推断可能确定了环境里原本未知的类型，S 要把这些发现带给后续表达式；只返回 τ 会丢失共享约束。

例如 Γ = {f : α} 下推断 f 1，只会得到 S = [α ↦ Int -> β]、结果 β，不能无依据地把返回类型也定为 Int。

下面的 Id 表示恒等替换；fresh 每次取全新变量；Γ[x ↦ σ] 表示添加或遮蔽一个绑定。常量按预先规定的类型处理，列表、积、递归需要额外分支。

W(Γ, x):
  ∀α1 ... αn. τ = Γ(x)
  β1, ..., βn = fresh()
  return (Id, [αi ↦ βi]τ)

W(Γ, λx. e):
  β = fresh()
  (S1, τ1) = W(Γ[x ↦ β], e)
  return (S1, S1β -> τ1)

W(Γ, e1 e2):
  (S1, τ1) = W(Γ, e1)
  (S2, τ2) = W(S1Γ, e2)
  β = fresh()
  U = unify(S2τ1, τ2 -> β)
  return (U ∘ S2 ∘ S1, Uβ)

W(Γ, let x = e1 in e2):
  (S1, τ1) = W(Γ, e1)
  σ = gen(S1Γ, τ1)
  (S2, τ2) = W((S1Γ)[x ↦ σ], e2)
  return (S2 ∘ S1, τ2)

Var 把量化变量换新，λ 参数没有量化变量因而仍共享原类型；Abs 必须用 S1 更新参数 β；App 在推实参前更新环境，并在合一前用 S2 更新函数类型；Let 必须对更新后的 S1Γ 做泛化。这四处共同保证先前得到的约束不会被遗忘。

手工跟踪：应用器与真正的函数组合

对 λf. λx. f x，设 f、x 与调用结果分别为 a、b、c，共产生三个新变量。从最内层向外返回：

子表达式／环境 关键动作 返回类型
f x，环境 {f : a, x : b} 合一 a = b -> c，得到 U = [a ↦ b -> c] c
λx. f x，环境 {f : a} 更新参数 b，组装函数类型 b -> c
λf. λx. f x，空环境 用 U 更新 a，再组装外层 (b -> c) -> b -> c

两处变量查找返回 Id，三个上表步骤都带出 U；在空环境将剩余 b、c 泛化，主类型方案为 ∀b c. (b -> c) -> b -> c。这是应用器（apply）：接受一个函数及其实参，然后调用它。

真正的组合是 compose = λf. λg. λx. f (g x)。若 x 的类型为 A，g x 为 B，f (g x) 为 C，则：

g : A -> B，f : B -> C
compose : ∀A B C. (B -> C) -> (A -> B) -> A -> C

中间类型 B 连接 g 的输出与 f 的输入，而不是要求两个函数的输入输出全部相同。

保留自由度：多态类型与实例化

考虑顶层定义 f g = g 2。先按课件的树为节点分配类型变量，再从节点生成约束：

flowchart TD
    Def["Fun：函数定义"] --> F["函数名 f : t0"]
    Def --> Param["形参绑定 g : t1"]
    Def --> App["应用 g 2 : t4"]

实线表示语法结构，虚线表示变量引用对应的绑定；图不是程序执行顺序。形参绑定 g 和函数体中的 g 是两个语法位置，但共享 t1。应用节点的类型 t4 是调用结果类型，不能与函数 g 的类型 t1 混淆。

Fun 节点： t0 = t1 -> t4       函数类型 = 形参类型 -> 函数体类型

程序要求 g 接受 Int，但没有限定其返回类型；f 返回的就是 g 的调用结果，因此两处 α 必须一致，不能擅自选定为 Int 或 Bool。

在基本 Hindley–Milner 系统中，推广可量化未被环境约束的类型变量。此例的顶层定义可写成类型方案 f : ∀α. (Int -> α) -> α，通常省略 ∀α。它表示每次使用 f 时，可以用一个具体类型或新的类型变量一致替换该次实例中的 α。

例如 add : Int -> Int 时，f add : Int；isEven : Int -> Bool 时，f isEven : Bool。不同使用可以分别实例化；同一次实例中相同的 α 始终代表同一类型。若传入 h : Bool -> Bool，仍会因 g 必须接受 Int 而失败。

多态保留的是程序允许的类型自由度，并不允许忽略已确定的约束，也不表示未知类型的值可接受任意操作。

同一个函数连续调用：约束如何连接

列表模式带来的约束

课件用 length [] = 0 与 length (x:rest) = 1 + (length rest) 引入列表。[α] 表示元素类型为 α 的列表；[] 是空列表；x:rest 表示一个表头 x 加上列表尾部 rest。在本课语言中，列表元素具有同一种类型。

flowchart TD
    Cons["列表模式 x:rest : γ"] --> Head["表头 x : α"]
    Cons --> Tail["尾部 rest : β"]

列表模式节点给出 γ = [α]、β = [α]：表头是元素，尾部与整个列表都是该元素类型的列表。rest 不必非空，例如 x:[] 只含一个元素；: 在这里是列表构造／匹配语法，不是类型标注。

在表达式中，: 是 cons（构造列表）的运算：左侧是一个元素，右侧是一个列表，把元素放到列表最前面。例如 1 : [2, 3] = [1, 2, 3]，1 : [] = [1]。1 : copy [2] 就是 1 : (copy [2])，待右侧得到 [2] 后构造 [1, 2]。

: 的类型为 A -> [A] -> [A]，而本课 append 的类型为 ([A] × [A]) -> [A]：前者连接一个元素与列表，后者连接两个列表。例如 append ([1], [2, 3]) 也得到 [1, 2, 3]，但参数结构不同。在定义左侧，x:xs 是模式，拆出表头与尾部；右侧的 x:xs 是构造表达式，将它们组成列表。

空列表没有元素来限定 α，因此其类型可以是 [α]，由上下文进一步约束；它既不是 Unit，也不必是 [Int]。

列表约束可以和函数体约束连接。例如 first (x:rest) = x 的输入类型为 [α]，结果类型为 α，因此 first : [α] -> α。此定义未处理空列表：能够推断类型，不代表模式覆盖完整或调用一定成功。

递归调用共享定义的类型：length

课件定义 length [] = 0、length (x:rest) = 1 + (length rest)。在基本 Hindley–Milner 推断中，检查递归函数体时先为 length 假设一个待求解的类型 δ，递归引用共享这个类型；推断结束后再推广可量化的变量。

加法使用的是递归调用的结果 β，并未使用表头 x，因此不会要求 α = Int。Bool 列表、Int 列表等都能作为 length 的输入。

空列表分支 length [] = 0 也给出列表输入、Int 输出；两个分支需具有一致的函数类型，最终 length : [α] -> Int。这些是类型约束，不需要实际展开递归调用或计算长度，也不能据此单独证明递归终止。

对照 sum [] = 0、sum (x:rest) = x + sum rest：这里加法直接使用了表头 x，因此元素类型也必须为 Int。将函数体展开为 ((+) x) (sum rest)，设 x 的类型为 α、递归结果为 β、函数体为 γ、sum 为 δ、部分应用 (+) x 为 κ：

函数定义：δ = [α] -> γ
递归调用：δ = [α] -> β
第一次加法调用：Int -> (Int -> Int) = α -> κ
第二次加法调用：κ = β -> γ

由第一次调用：α = Int，κ = Int -> Int
由第二次调用：β = Int，γ = Int
因此 sum : [Int] -> Int

不能将 (+) x 的类型直接写成 α -> Int：α 是已传入实参 x 的类型，部分应用的类型应从加法函数类型及第一次调用约束中求出。length 只对计数结果做加法，sum 对列表元素做加法，这解释了两者输入元素类型的差别。

多个模式分支必须合并为同一个函数类型

课件的 append 接收一个包含两个列表的二元组：

append ([], r) = r
append (x:xs, r) = x : append (xs, r)

先收集各分支带来的类型形状，再要求同一个函数的所有分支类型一致。第一分支中，空列表类型为 [a]，r 的类型暂记 b，结果也是 b。第二分支中，x 的类型为 c、xs 为 [c]、r 暂记 d；由于返回表达式以 x 为表头，递归结果和整个结果都必须为 [c]。

flowchart TD
    Def["append 的共同类型 δ"] --> First["分支一约束：δ = ([a] × b) → b"]
    Def --> Second["分支二约束：δ = ([c] × d) → [c]"]
    First --> Merge["合一：a = c；b = d；b = [c]"]
    Second --> Merge
    Merge --> Result["δ = ([a] × [a]) → [a]"]

两种输入形状属于同一个函数，不能各自保持互不相容的类型。这些分支类型形状是合并前的约束，不是忽略其余约束后独立成立的完整多态定义；递归调用也必须共享 append 的待求解类型。

例如两个 Int 列表或两个 Bool 列表都满足规则；一个 Int 列表与一个 Bool 列表不能合并成此语言中的同质列表。两个空列表的元素类型尚未确定，可由其他输入或使用上下文限定。

最一般类型：其他合法类型都可由它实例化

主类型（principal type），也称最一般类型，保留程序允许的类型自由度；更具体的合法类型都能通过一致替换其中可量化的类型变量得到。它不是选择一个具体类型作为默认值，也不是允许忽略程序约束。

课件定义：

map (f, []) = []
map (f, x:xs) = f x : map (f, xs)

设 x 的类型为 A，f x 的类型为 B，则 f 必须具有 A -> B 类型，xs 为 [A]，递归结果为 [B]，整个结果也为 [B]。空列表分支与这些约束一致。

flowchart TD
    Input["二元组输入：(f, 输入列表)"] --> F["f : A → B"]
    Input --> List["输入列表 : [A]"]
    Body["结果构造 f x : map (f, xs) : [B]"] --> Head["调用 f x : B"]
    Body --> Tail["递归调用 map (f, xs) : [B]"]

因此 map : ((A -> B) × [A]) -> [B]。A 与 B 没有被要求相同，也没有被限定为某一种基本类型。

例如替换 A = Bool、B = Int，得到 ((Bool -> Int) × [Bool]) -> [Int]；只替换 B = Int，则保留 A 的自由度，得到 ((A -> Int) × [A]) -> [Int]。这些都是主类型的实例，但限制比主类型更多。

判断某个类型是否为实例，要检查所有位置的一致替换。例如 ((Int -> Bool) × [Int]) -> [Int] 不是上述 map 类型的实例：f 的输出把 B 限定为 Bool，结果列表却把 B 限定为 Int。

实例化时应按位置对齐：传入 isEven : Int -> Bool 就令 A -> B = Int -> Bool，得到 A = Int、B = Bool；输入为 [Int]，输出为 [Bool]。A 是输入元素类型，B 是 f 返回的单个结果类型，不能把整个函数类型当作 A、整个列表类型当作 B。传入 double : Int -> Int 则得到 A = B = Int，输出为 [Int]。

类型合法与程序意图：写错的 reverse

课件给出以下定义：

reverse [] = []
reverse (x:xs) = reverse xs

非空分支的表头 x 未出现在函数体中：

flowchart TD
    Def["定义 reverse : δ"] --> Pattern["形参 x:xs : [A]"]
    Pattern --> Head["x : A（函数体未使用）"]
    Pattern --> Tail["xs : [A]"]
    Def --> Body["函数体：递归调用 reverse xs : R"]
    Body --> Ref["reverse : δ"]
    Body --> Arg["xs : [A]"]
    Ref -.->|共享定义类型| Def
    Arg -.-> Tail

函数定义与递归调用都给出 δ = [A] -> R，没有建立输入元素 A 与结果元素之间的联系。空列表分支的结果为 [B]，因此 R = [B]，最终主类型是 reverse : [A] -> [B]。

运行在有限列表上时，该定义会逐个丢弃表头，最终返回空列表。例如 [1, 2] → [2] → [] → 返回 []；并未实现逆序。推断类型没有矛盾，但输入输出元素类型互不关联，与列表逆序通常预期的 [A] -> [A] 不符，提示应检查实现。

对照 copy [] = []、copy (x:xs) = x : copy xs：表头 x 的类型为 A，列表构造节点要求尾部 copy xs 为 [A]，整个结果也为 [A]，所以 copy : [A] -> [A]。建立输入输出元素类型联系的是列表构造节点。此函数保留原顺序，仍不是逆序函数，说明同一个类型可以对应不同功能。

类型检查失败表示程序违反当前类型系统的规则；推断类型与预期类型不同则不必然意味着检查失败。例如上述错误 reverse 的 [A] -> [B] 可实例化为 [A] -> [A]，但通过这一标注的检查仍不能保证元素保留或顺序正确。类型可以提示实现与意图的差异，功能正确性还需另行验证。

推断能力依赖语言规则

本课示例使用无重载的简化 Haskell 子集，给加法固定类型 Int -> Int -> Int。这使约束生成与合一可以直接确定加法操作数为 Int。

课件最后指出，完整 Haskell 使用类型类支持重载，推断需要处理相应约束，不能直接套用本课的整数加法假设。类型变量保留的选择也须满足操作本身的要求，并非任何类型都能相加。

基本 Hindley–Milner 系统中，递归函数体的各次递归引用共享待求解的函数类型；多态递归则允许递归使用不同类型实例，不属于这里演示的自动推断范围，一般需要适当的类型标注。语言功能越丰富，推断算法可能需要扩展或额外标注；不能把“本课不写类型也能推断”推广为“任意语言功能都不需要标注”。

可靠性、主类型与副作用边界

在上述 HM 核心中，W 的可靠性是“成功返回的结果可按规则推导”；完备性与主类型性质是“可类型化时能成功，并给出最一般的结果”，主类型方案在量化变量改名等意义下唯一。可类型化性可判定：W 在有限步内成功返回或报告失败，程序员不必预先标注每个类型。这些保证依赖语言、环境及类型规则，不是所有具有推断功能的语言都自动继承。Damas–Milner 原论文针对其纯函数式核心证明了相关性质。

推断算法的可靠性与语言的运行时类型安全还要区分：后者需要类型规则和求值语义之间的证明；即使良类型程序不因所建模的类型错误卡住，也不能推出终止、完整模式覆盖或业务正确性。

若加入可变引用，任意 let 泛化可能破坏安全性。以 ML 风格伪代码为例，错误地让同一引用获得可反复实例化的方案 ∀α. Ref<[α]>，就可能发生：

let r = ref [] in
  r := [1];
  not (head (!r))

写入时把 r 当整数列表引用，读取时又把同一 r 当布尔列表引用，运行时就会把整数交给 not。通常的值限制只允许对非扩张的值表达式等安全情况泛化；OCaml 的宽松值限制还利用协变性允许更多情况，不能概括成“所有非值都永远单态”。OCaml 的多态限制说明解释了弱类型变量与这两种限制。

HM 的参数多态、联合／交叉类型的子类型和重载契约是不同机制。基本 HM 不包含一般子类型、重载或高秩多态；扩展系统需要另外处理约束并可能要求标注。现实语言采用 HM 式局部推断，也不意味着整门语言就是纯 HM。

推断效率：常见表现与最坏情况分开

课件指出，Hindley–Milner 类型推断的最坏情况可达到指数级，尤其要注意嵌套多态声明带来的类型增长；同时指出实际程序中的表现通常较好。这是对实践表现的概括，不是对所有程序的线性时间保证。

程序文本短，不代表推断过程中涉及的类型结构也小。多态定义在不同使用位置被实例化，嵌套组合可能使推断所需处理的类型结构快速增长。不能仅凭每条局部约束容易处理，就断言整个推断过程总是线性。

最坏情况复杂度描述算法面对困难输入的增长上界／难度，实际性能要结合程序与实现判断；既不能从常见程序推断很快得出“总是很快”，也不能从最坏情况指数级得出“所有程序都很慢”。
