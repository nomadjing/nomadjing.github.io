问题与求解目标

这篇论文研究如何精确求解过程间数据流分析（interprocedural dataflow analysis）问题：在包含过程调用、参数、局部变量和递归的程序中，计算各程序点的数据流信息。这里的“精确”是指对给定的分析模型，汇合所有合法路径上的分析结果；合法路径要求过程返回到最近一次尚未完成的调用所对应的位置。

论文关注的问题类别称为 IFDS（Interprocedural, Finite, Distributive, Subset）：分析跨越过程边界（Interprocedural）；数据流事实构成有限集合 DDD（Finite），各程序点的分析状态是 DDD 的子集（Subset）；传递函数 f:2D→2Df:2^D\to 2^Df:2D→2D 对汇合算子满足分配律（Distributive）。例如，汇合采用并集时，要求 f(A∪B)=f(A)∪f(B)f(A\cup B)=f(A)\cup f(B)f(A∪B)=f(A)∪f(B)；汇合也可以采用交集，此时要求相应的交集分配律。论文为这一类问题提供了基于图可达性的多项式时间求解算法。

问题示例：可能未初始化变量分析

以原论文 Figure 1(a) 的程序为例：

declare g: integer

program main
begin
    declare x: integer
    read(x)
    call P(x)
end

procedure P(value a: integer)
begin
    if (a > 0) then
        read(g)
        a := a - g
        call P(a)
        print(a, g)
    fi
end

未初始化问题指的是：在每个程序点，哪些变量可能尚未初始化？ 用集合 SSS 记录这些变量，v∈Sv\in Sv∈S 表示 vvv 可能未初始化。例如，执行 read(g) 后，ggg 从集合中移除；执行 a := a - g 后，如果赋值前的 aaa 或 ggg 可能未初始化，那么赋值后的 aaa 也可能未初始化。

程序既包含 main 对 P 的调用，也包含 P 对自身的递归调用，因此分析需要考虑未初始化信息如何经过参数传递、过程调用和返回继续传播。

程序的图表示：supergraph

程序表示为有向图 G∗=(N∗,E∗)G^*=(N^*,E^*)G∗=(N∗,E∗)，称为 supergraph。它由各个过程的控制流图连接而成：每个过程 ppp 有唯一入口 sps_psp​ 和出口 epe_pep​，其他节点表示语句或条件；一次过程调用拆成调用节点 ccc 和返回位置节点 rrr。

supergraph 即 IFDS 语境下的 ICFG（过程间控制流图）

图中的 main 和 P 各有一份CFG（控制流图）。即使 P 递归调用自身，也复用 P 的这份图；不同调用对应不同的调用节点和返回位置。

调用相关的三类边

除普通过程内控制流边外，每个调用引入以下三类边。其中 call-to-start 和 exit-to-return-site 跨越过程边界，call-to-return-site 则连接调用者内部的两个节点。

边 连接 传递的信息
call-to-start c→spc\to s_pc→sp​ 将调用处的信息传入被调过程，包括实参与形参的对应
exit-to-return-site ep→re_p\to rep​→r 将被调过程出口的信息传回调用者
call-to-return-site c→rc\to rc→r 保留调用者的局部信息，在返回位置与被调过程传回的信息汇合

例如，main 中的调用节点是 n2n_2n2​，返回位置是 n3n_3n3​；P 内部递归调用的节点是 n7n_7n7​，返回位置是 n8n_8n8​。两次调用都连接 P 的入口和出口，但各自有对应的返回位置。

call-to-return-site 边用于保留调用者侧的信息。 例如，按值传递的调用者局部变量无需随着被调过程的局部状态一起更新，可以通过这条边保留；被调过程对全局变量产生的影响则通过返回边传回。返回位置汇合这两路信息，因此绕过边并不表示忽略被调过程的影响。

合法路径：valid path

supergraph 中连通的路径未必符合调用与返回规则。valid path 要求每次返回都匹配最近一次尚未完成的调用，但允许路径停在被调过程内部，留下尚未返回的调用。same-level valid path 还要求起点和终点在同一过程，并且路径中的调用全部匹配返回。

例如，从 main 的 n2n_2n2​ 调用 P 后，应返回 n3n_3n3​；若沿 eP→n8e_P\to n_8eP​→n8​ 返回到 P 内部递归调用的返回位置，虽然图上连通，却不是 valid path。

将调用与对应返回记为同编号的左右括号，可以直观区分：

(1 (2 )2 )1    same-level valid，也是 valid
(1 (2 )2       valid，但不是 same-level valid
(1 )2          不 valid：调用与返回不匹配

这里的 valid 只约束调用与返回结构，不保证沿途分支条件在真实执行中可同时满足。最终分析汇合程序入口到目标节点的 valid paths 上的信息；same-level valid paths 则用于描述过程摘要。

在 supergraph 上定义 IFDS 问题

supergraph 描述程序的控制流；要定义具体分析，还需要指定数据流事实、边上的传递函数，以及信息汇合的方式。论文将一个 IFDS 问题实例表示为五元组：

IP=(G∗,D,F,M,⊓).IP=(G^*,D,F,M,\sqcap). IP=(G∗,D,F,M,⊓).

前者消除 ggg 的未初始化事实，后者根据赋值前的操作数状态更新 aaa。这样，同一份程序图配上不同的事实域和边函数，就能描述不同的数据流分析问题。

分配函数的关系表示

以下讨论汇合算子为并集的情形，即 f(A∪B)=f(A)∪f(B)f(A\cup B)=f(A)\cup f(B)f(A∪B)=f(A)∪f(B)；交集情形可以先转化为对应的并集问题。

分配性与逐事实传播

对非空有限集合 SSS，反复使用分配律可得：

f(S)=f(⋃d∈S{d})=⋃d∈Sf({d}).f(S)=f\left(\bigcup_{d\in S}\{d\}\right) =\bigcup_{d\in S}f(\{d\}). f(S)=f(d∈S⋃​{d})=d∈S⋃​f({d}).

f(∅)f(\varnothing)f(∅) 不一定为空，例如程序入口即使收到空输入，也会产生未初始化事实 {x,g}\{x,g\}{x,g}。由分配律又有：

f({d})=f(∅)∪f({d}),f(\{d\})=f(\varnothing)\cup f(\{d\}), f({d})=f(∅)∪f({d}),

所以 f(∅)⊆f({d})f(\varnothing)\subseteq f(\{d\})f(∅)⊆f({d})。将空输入也包含在内，统一写成：

f(S)=f(∅)∪⋃d∈Sf({d}).f(S)=f(\varnothing)\cup\bigcup_{d\in S}f(\{d\}). f(S)=f(∅)∪d∈S⋃​f({d}).

函数对任意集合的作用，完全由空输入和各个单事实输入的输出决定。 因此可以只记录“哪个输入事实能产生哪个输出事实”，用二元关系表示函数。

这也解释了为什么需要分配性：若一个函数必须同时看到 a,ba,ba,b 才产生 ccc，但单独输入 {a}\{a\}{a} 或 {b}\{b\}{b} 都不产生 ccc，逐事实传播就无法恢复它的行为；这种函数不满足并集分配律。

关系复合与函数复合

程序沿一条路径执行多条语句，分析就要依次应用多个函数。关系表示不仅要能替换单个函数，还必须保持这种复合行为。

从数据流分析到 realizable-path 可达性

构造 exploded supergraph

supergraph 中，节点 nnn 表示程序点，边 m→nm\to nm→n 携带集合函数 M(m,n)M(m,n)M(m,n)。将每条边的函数替换成关系，并把相邻边上的同一事实节点接起来，就得到 exploded supergraph。

记扩展后的图为 G#=(N#,E#)G^\#=(N^\#,E^\#)G#=(N#,E#)。每个程序点展开为一组“程序点、事实”节点：

N#=N∗×(D∪{0}).N^\#=N^*\times(D\cup\{0\}). N#=N∗×(D∪{0}).

即原来的 nnn 变成：

(n,0),(n,d1),…,(n,d∣D∣).(n,0),\quad(n,d_1),\quad\ldots,\quad(n,d_{|D|}). (n,0),(n,d1​),…,(n,d∣D∣​).

原图的一条边 m→nm\to nm→n，按其函数的关系表示展开：

E#={((m,d1),(n,d2))∣(m,n)∈E∗, (d1,d2)∈RM(m,n)}.E^\#= \{((m,d_1),(n,d_2)) \mid(m,n)\in E^*,\ (d_1,d_2)\in R_{M(m,n)}\}. E#={((m,d1​),(n,d2​))∣(m,n)∈E∗, (d1​,d2​)∈RM(m,n)​}.

例如，a:=a−ga:=a-ga:=a−g 所在的 n6→n7n_6\to n_7n6​→n7​ 包含以下事实边：

扩展图的一条事实路径不需要携带整个集合。分配性保证：某个输出事实如果能产生，就能找到一条对应的单事实传播链；若它在中途无条件产生，这条链可以先沿 000 通道到达生成它的位置。

保留调用与返回约束

构造扩展图不会自动消除原图中的错误调用与返回组合。每条扩展边仍对应一条原图边，因此可以把扩展图路径投影回 supergraph，检查其调用与返回是否匹配。

论文将投影后为 valid path 的扩展图路径称为 realizable path；same-level realizable path 则对应 same-level valid path。两者采用相同的调用与返回约束，只是分别用于事实图和程序图。

例如，原图中从 n2n_2n2​ 进入 P，却从 ePe_PeP​ 返回 n8n_8n8​，仍可能在扩展图中形成连通路径，但其投影不是 valid path，因此不能参与求解。这里的 realizable 同样不意味着检查了所有分支条件的语义可行性。

汇合所有合法路径

令 IVP⁡(smain,n)\operatorname{IVP}(s_{\mathrm{main}},n)IVP(smain​,n) 表示入口到 nnn 的所有 valid paths。对于并集分析，MVP 解为：

MVP⁡n=⋃q∈IVP⁡(smain,n)pf⁡q(∅).\operatorname{MVP}_n= \bigcup_{q\in\operatorname{IVP}(s_{\mathrm{main}},n)} \operatorname{pf}_q(\varnothing). MVPn​=q∈IVP(smain​,n)⋃​pfq​(∅).

一个事实属于这个并集，当且仅当至少有一条 valid path 能把它传播到目标节点。将前面单条路径上的等价关系代入，就得到原论文 Theorem 3.8：

d∈MVP⁡n  ⟺  (smain,0)⇝realizable(n,d),d∈D.d\in\operatorname{MVP}_n \iff (s_{\mathrm{main}},0) \overset{\mathrm{realizable}}{\leadsto}(n,d), \qquad d\in D. d∈MVPn​⟺(smain​,0)⇝realizable(n,d),d∈D.

这个等价可以从两个方向理解：

  • 若 d∈MVP⁡nd\in\operatorname{MVP}_nd∈MVPn​，则某条 valid path qqq 的结果包含 ddd。关系复合保证扩展图中存在一条投影为 qqq 的事实传播链；因为 qqq 合法，这条链是 realizable path。
  • 若存在到 (n,d)(n,d)(n,d) 的 realizable path，将其投影为原图中的 valid path qqq。每条关系边都保留了对应函数的作用，所以 d∈pf⁡q(∅)d\in\operatorname{pf}_q(\varnothing)d∈pfq​(∅)，从而属于 MVP⁡n\operatorname{MVP}_nMVPn​。

以原论文的未初始化变量分析为例，MVP⁡eP={g}\operatorname{MVP}_{e_P}=\{g\}MVPeP​​={g}。可以根据程序解释：P 的条件为假时会直接退出，保留 ggg 的未初始化状态；进入条件分支时则先执行读取，再进行赋值。扩展图中相应地存在到 (eP,g)(e_P,g)(eP​,g) 的 realizable path，而不存在到 (eP,a)(e_P,a)(eP​,a) 的 realizable path。

因此，求解对象已经从“在所有合法程序路径上计算、汇合数据流集合”，转化成了 “从 (smain,0)(s_{\mathrm{main}},0)(smain​,0) 出发，寻找沿 realizable paths 可达的普通事实节点”。函数表示和路径转换都保持等价；接下来的 Tabulation 算法负责高效求解这个带调用与返回约束的可达性问题。

Tabulation 算法

前面将 IFDS 转化为 realizable-path 可达性问题，但普通图搜索不能保证调用与返回匹配；显式记录完整调用栈又会遇到递归带来的无界调用序列。Tabulation 是一种worklist算法，记录过程内的路径关系，并将完整调用的效果保存为摘要边，供调用者复用。

PathEdge、SummaryEdge 与 WorkList

一条PathEdge（路径边）具有下面的形式：

(sp,d1)→(n,d2)∈PathEdge.(s_p,d_1)\to(n,d_2)\in\mathrm{PathEdge}. (sp​,d1​)→(n,d2​)∈PathEdge.

它表示：从过程 ppp 的入口事实 d1d_1d1​ 出发，可以沿 same-level realizable path 到达本过程的 (n,d2)(n,d_2)(n,d2​)。 同时，入口 (sp,d1)(s_p,d_1)(sp​,d1​) 已经能够从程序入口沿 realizable path 到达。因此，这条路径边也是一条全局合法传播路径的后缀。

入口事实 d1d_1d1​ 不能省略。相同的出口事实可能来自不同入口事实，而调用者返回时需要知道“哪种入口能产生哪种出口”，才能与调用边、返回边正确拼接。只记录 (n,d2)(n,d_2)(n,d2​) 已可达，会丢失这种对应关系。

一条摘要边具有下面的形式，其中 ccc 是调用点，r=returnSite⁡(c)r=\operatorname{returnSite}(c)r=returnSite(c)：

(c,d4)→(r,d5)∈SummaryEdge.(c,d_4)\to(r,d_5)\in\mathrm{SummaryEdge}. (c,d4​)→(r,d5​)∈SummaryEdge.

它概括一次匹配的“进入被调过程、在内部完成传播、返回对应位置”的效果。它位于调用者的调用点与返回位置之间，已经包含参数传入和返回时的事实映射；

WorkList 存放已经发现、但尚未处理的路径边。Propagate 负责去重：只有新的路径边才同时加入 PathEdge 和 WorkList。PathEdge 记录结论，WorkList 驱动这些结论产生新的结论。

算法使用的辅助函数为：

函数 含义
procOf⁡(n)\operatorname{procOf}(n)procOf(n) 节点 nnn 所属的过程
calledProc⁡(c)\operatorname{calledProc}(c)calledProc(c) 调用点 ccc 调用的过程
returnSite⁡(c)\operatorname{returnSite}(c)returnSite(c) 调用点 ccc 对应的返回位置
callers⁡(p)\operatorname{callers}(p)callers(p) 所有调用过程 ppp 的调用点

初始化与普通传播

初始路径边是：

(smain,0)→(smain,0).(s_{\mathrm{main}},0)\to(s_{\mathrm{main}},0). (smain​,0)→(smain​,0).

它表示零长度路径，作为整个分析的起点。入口边上的关系随后产生 x,gx,gx,g 等普通事实，无需提前为每个过程、每个事实启动分析。

普通节点使用 [33]–[37]：若已经知道入口到 (n,d2)(n,d_2)(n,d2​) 的路径边，再沿一条扩展图边到 (m,d3)(m,d_3)(m,d3​)，就得到：

(sp,d1)→(n,d2)∈PathEdge(n,d2)→(m,d3)∈E#(sp,d1)→(m,d3)∈PathEdge.\frac{ (s_p,d_1)\to(n,d_2)\in\mathrm{PathEdge} \qquad (n,d_2)\to(m,d_3)\in E^\# }{ (s_p,d_1)\to(m,d_3)\in\mathrm{PathEdge} }. (sp​,d1​)→(m,d3​)∈PathEdge(sp​,d1​)→(n,d2​)∈PathEdge(n,d2​)→(m,d3​)∈E#​.

这里始终保留原来的入口 (sp,d1)(s_p,d_1)(sp​,d1​)，只向前推进路径边的终点。返回位置本身也属于这一普通节点分支，可以继续向后传播。

到达调用点

处理调用点 ccc 时，算法同时做两件事。

[14]–[16] 沿 call-to-start 边确定被调过程 qqq 的入口事实 d3d_3d3​，然后通过 Propagate 登记：

(sq,d3)→(sq,d3).(s_q,d_3)\to(s_q,d_3). (sq​,d3​)→(sq​,d3​).

这相当于启动“以 d3d_3d3​ 为入口事实”的过程内分析。路径边的起点改为被调过程入口，而不是继续携带调用者入口；调用者到调用点的对应关系仍保存在原来的 PathEdge 中。相同入口事实再次到达时，这条自环已存在，Propagate 不会重复启动分析。

[17]–[19] 则留在调用者内部，沿原有 call-to-return-site 边或已知 SummaryEdge 到达返回位置，并保留调用者的入口信息：

(sp,d1)→(c,d2)+(c,d2)→(r,d3)⟹(sp,d1)→(r,d3).(s_p,d_1)\to(c,d_2) \quad+\quad (c,d_2)\to(r,d_3) \quad\Longrightarrow\quad (s_p,d_1)\to(r,d_3). (sp​,d1​)→(c,d2​)+(c,d2​)→(r,d3​)⟹(sp​,d1​)→(r,d3​).

因此，一次调用既可能触发新的被调过程分析，也可以立即复用已经存在的摘要；

到达过程出口并生成摘要

假设刚处理的路径边是：

(sp,d1)→(ep,d2).(s_p,d_1)\to(e_p,d_2). (sp​,d1​)→(ep​,d2​).

它给出过程 ppp 从入口事实 d1d_1d1​ 到出口事实 d2d_2d2​ 的完整 same-level 传播效果。[22]–[25] 对每个调用点 ccc，寻找能与这条路径边接上的调用边和返回边：

(c,d4)→(sp,d1)∈E#,(ep,d2)→(r,d5)∈E#,r=returnSite⁡(c).(c,d_4)\to(s_p,d_1)\in E^\#, \qquad (e_p,d_2)\to(r,d_5)\in E^\#, \qquad r=\operatorname{returnSite}(c). (c,d4​)→(sp​,d1​)∈E#,(ep​,d2​)→(r,d5​)∈E#,r=returnSite(c).

三段拼接后，登记摘要边：

(c,d4)→(r,d5)∈SummaryEdge.(c,d_4)\to(r,d_5)\in\mathrm{SummaryEdge}. (c,d4​)→(r,d5​)∈SummaryEdge.

调用边与返回边使用的是同一个调用点 ccc，被调过程内部又是 same-level 路径，所以整段传播满足调用与返回匹配规则。算法不会直接从出口沿任意返回边跳走。

[26]–[28] 再查找已经到达 (c,d4)(c,d_4)(c,d4​) 的调用者路径边，将它们与新摘要拼接，继续推进调用者：

(sprocOf⁡(c),d3)→(c,d4)+(c,d4)→(r,d5)⟹(sprocOf⁡(c),d3)→(r,d5).(s_{\operatorname{procOf}(c)},d_3)\to(c,d_4) \quad+\quad (c,d_4)\to(r,d_5) \quad\Longrightarrow\quad (s_{\operatorname{procOf}(c)},d_3)\to(r,d_5). (sprocOf(c)​,d3​)→(c,d4​)+(c,d4​)→(r,d5​)⟹(sprocOf(c)​,d3​)→(r,d5​).

摘要的登记与复用

处理过程出口时，[22]–[25] 遍历该过程的所有调用点，将当前入口到出口的路径边与匹配的调用边、返回边拼接，得到摘要并存入 SummaryEdge。无论对应的调用事实是否已经到达，摘要都会被保存。

随后，[26]–[28] 将新摘要接到已有的调用者路径边上，传播到返回位置。对应的调用事实若在之后到达，则由调用点分支 [17]–[19] 读取已保存的摘要，继续传播。

对照未初始化变量示例

从 main 的入口出发，入口函数生成 ggg 的未初始化事实；读取 xxx 不改变 ggg，于是得到：

在出口处，将这条路径边与 main 的调用边、对应返回边拼接，生成：

P 内部的递归调用点 n7n_7n7​ 同样可以匹配入口事实 ggg 和出口事实 ggg，所以原算法还可以安装条件性摘要：

(n7,g)→(n8,g).(n_7,g)\to(n_8,g). (n7​,g)→(n8​,g).

对于递归调用实际到达的入口事实，例如特殊事实 000，算法只复用或登记同一条 (sP,0)→(sP,0)(s_P,0)\to(s_P,0)(sP​,0)→(sP​,0) 自环。不同递归深度不会创建新的入口事实节点；新发现的过程内路径和摘要继续通过工作列表传播，直到稳定。

取出分析结果

工作列表为空后，[6]–[8] 收集每个程序点 nnn 的路径边终点：

Tabulation 算法的成本

分析规模与计数方式

记程序节点数为 NNN，supergraph 的边数为 EEE，调用点数为 Call\mathrm{Call}Call。为避免与事实集合 DDD 混淆，下面用 d=∣D∣d=|D|d=∣D∣ 表示事实数量；特殊事实 000 不改变渐近上界。论文假设基本集合操作具有单位成本。(Reps et al., 1995)

一条 PathEdge 由过程入口事实、目标程序点和目标事实确定，因此至多有：

O(Nd2)O(Nd^2) O(Nd2)

条。每条路径边只会进入 WorkList 一次，这既保证算法终止，也限制了工作列表的处理次数。但路径边只插入一次，不代表只会尝试生成一次：不同传播路线可能反复推出同一条边，去重操作本身仍有成本。附录因此分别累计工作列表操作、摘要安装和闭包传播的总成本，而不是直接用最坏单次循环成本乘循环次数。(Reps et al., 1995)

将每个过程看成多源可达性问题

对于过程 ppp，每个入口节点：

(sp,a),a∈D∪{0}(s_p,a),\qquad a\in D\cup\{0\} (sp​,a),a∈D∪{0}

都是一个可能的传播起点，附录称其为 anchor site。固定一个入口事实后，PathEdge 就记录从这个起点可以到达哪些事实节点。传播使用过程内边、call-to-return-site 边，以及分析过程中陆续加入的 SummaryEdge。图中的边只增加、不删除，因此可以把算法理解为：同时维护各个过程上、不断增加摘要边的多源可达性问题。 (Reps et al., 1995)

这个视角把成本分为两部分：沿现有边扩展可达性，以及生成新摘要并通知已经到达调用点的路径。工作列表操作可以计入触发它们的这些操作，不必再单独乘上一层循环次数。(Reps et al., 1995)

闭包传播的成本

先固定一个入口 (sp,a)(s_p,a)(sp​,a)。每次向前传播，都是把一条已有路径边与一条事实边拼接：

(sp,a)⇝(m,b),(m,b)→(n,c).(s_p,a)\leadsto(m,b), \qquad (m,b)\to(n,c).(sp​,a)⇝(m,b),(m,b)→(n,c).

对于这个固定起点，每个中间节点 (m,b)(m,b)(m,b) 只会作为路径边终点处理一次，因此可以把所有传播尝试累计到被扫描的边上。一般分配函数的关系最多包含 O(d2)O(d^2)O(d2) 条边，所以过程内原有边带来的成本为 O(Epd2)O(E_p d^2)O(Ep​d2)；每个调用点又至多具有 O(d2)O(d^2)O(d2) 条摘要边，带来 O(Callpd2)O(\mathrm{Call}_p d^2)O(Callp​d2) 的成本。这里已经包含多条边反复尝试生成同一条 PathEdge 的情况。(Reps et al., 1995)

每个过程至多有 d+1d+1d+1 个入口起点，对所有过程求和：

Tclosure=∑pO ⁣(d(Epd2+Callpd2))=O ⁣((E+Call)d3)=O(Ed3).\begin{aligned} T_{\mathrm{closure}} &= \sum_p O\!\left( d(E_p d^2+\mathrm{Call}_p d^2) \right)\\ &= O\!\left((E+\mathrm{Call})d^3\right)\\ &= O(Ed^3). \end{aligned}Tclosure​​=p∑​O(d(Ep​d2+Callp​d2))=O((E+Call)d3)=O(Ed3).​

因此，闭包传播中三个事实维度分别来自：入口事实、当前事实、后继事实。这是对附录计数的直观理解；正式上界来自对所有起点及其扫描边的累计。(Reps et al., 1995)

摘要安装的成本

生成摘要需要拼接调用边、被调过程的入口到出口路径边，以及返回边：

(c,a)→(sp,b)⇝(ep,c′)→(r,e).(c,a)\to(s_p,b) \leadsto(e_p,c') \to(r,e).(c,a)→(sp​,b)⇝(ep​,c′)→(r,e).

仅知道摘要数量至多为 O(Call d2)O(\mathrm{Call}\,d^2)O(Calld2) 还不够，因为同一条摘要可能由不同的入口、出口事实组合反复推导出来。附录引入参数 BBB，衡量过程边界上的事实映射宽度：它是所有调用关系中非零节点的最大出度，以及所有返回关系中非零节点的最大入度，两者的最大值。最坏情况下 B=dB=dB=d。(Reps et al., 1995)

固定调用点和摘要端点 a,ea,ea,e，且两者都非零时，调用关系至多给出 BBB 个入口事实，返回关系至多给出 BBB 个出口事实，因此至多检查 B2B^2B2 种中间组合。附录另外计算了涉及 000 的情况，得到所有摘要候选检查的总成本：

O(Call B2d2).O(\mathrm{Call}\,B^2d^2). O(CallB2d2).

摘要真正首次插入后，还需要连接已经到达调用点的 PathEdge。每条摘要至多匹配 O(d)O(d)O(d) 个调用者入口事实，而摘要至多有 O(Call d2)O(\mathrm{Call}\,d^2)O(Calld2) 条，因此这部分成本为：

O(Call d3).O(\mathrm{Call}\,d^3). O(Calld3).

合起来，摘要安装成本为：

Tsummary=O(Call B2d2+Call d3).T_{\mathrm{summary}} = O(\mathrm{Call}\,B^2d^2+\mathrm{Call}\,d^3).Tsummary​=O(CallB2d2+Calld3).

这里分别计算了“反复发现摘要候选”和“首次安装摘要后的传播”，避免把去重后的摘要数量误当成全部计算量。(Reps et al., 1995)

一般 IFDS 问题的时间上界

合并闭包传播和摘要安装，附录首先得到：

T=O(Call B2d2+Ed3).T= O(\mathrm{Call}\,B^2d^2+Ed^3).T=O(CallB2d2+Ed3).

不能直接把 B≤dB\le dB≤d 代入这个式子，就声称得到 O(Ed3)O(Ed^3)O(Ed3)，因为第一项会变成 O(Call d4)O(\mathrm{Call}\,d^4)O(Calld4)。附录还使用了一步连接结构变换：将过程间的事实映射当作独立的连接过程处理，使新连接的带宽为 111，从而将上界改进为：

T=O(Call Bd2+Ed3).T= O(\mathrm{Call}\,Bd^2+Ed^3).T=O(CallBd2+Ed3).

再利用 Call≤E\mathrm{Call}\le ECall≤E 和 B≤dB\le dB≤d，才得到论文表中的一般上界：

T=O(Ed3).\boxed{T=O(Ed^3)}. T=O(Ed3)​.

因此，O(Ed3)O(Ed^3)O(Ed3) 的推导既依赖逐类累计成本，也依赖附录最后对过程连接的处理。(Reps et al., 1995)

稀疏性如何降低成本

一般分配函数允许一个事实影响很多其他事实，关系可能有 O(d2)O(d^2)O(d2) 条边。但许多语句只改变少量状态，其关系更接近恒等关系。论文将普通过程内边和 call-to-return-site 边上、从非零事实节点出发的关系边总数至多为 hdhdhd 的问题称为 hhh-sparse。这个定义约束的是边的总数，不要求每个节点的出度都不超过 hhh，也不直接约束调用边和返回边。(Reps et al., 1995)

例如，在节点表示单条语句或条件、且没有别名的前提下，可能未初始化变量分析是 222-sparse：一个变量的未初始化状态至多影响它自身，以及当前赋值的目标变量。a := a-g 中的 g→gg\to gg→g 和 g→ag\to ag→a 就体现了这种结构。(Reps et al., 1995)

第 5 节的 Table 5.2 将不同结构下的成本归纳如下，其中过程内、过程间两列分别对应两种分析场景：

函数类别 过程内分析 过程间分析
一般分配函数 O(Ed2)O(Ed^2)O(Ed2) O(Ed3)O(Ed^3)O(Ed3)
hhh-sparse O(hEd)O(hEd)O(hEd) O(Call d3+hEd2)O(\mathrm{Call}\,d^3+hEd^2)O(Calld3+hEd2)
过程内可分离／过程间局部可分离 O(Ed)O(Ed)O(Ed) O(Ed)O(Ed)O(Ed)

来源：（Reps et al., 1995），Table 5.2。

对于 hhh-sparse 问题，稀疏性减少了普通边的扫描量，但过程摘要仍可能包含不同事实之间的密集依赖，所以过程间上界还保留 O(Call d3)O(\mathrm{Call}\,d^3)O(Calld3)。局部可分离问题则具有更强的逐分量依赖结构，能得到 O(Ed)O(Ed)O(Ed)；不能仅仅把 h=1h=1h=1 代入稀疏问题的公式，就推出这一结果。 后一点是对表中两类结构差异的解释。(Reps et al., 1995)

空间成本

一般分配问题中，主要数据结构的空间上界为：

数据结构 空间上界
exploded supergraph O(Ed2)O(Ed^2)O(Ed2)
PathEdge O(Nd2)O(Nd^2)O(Nd2)
WorkList O(Nd2)O(Nd^2)O(Nd2)
SummaryEdge O(Call d2)O(\mathrm{Call}\,d^2)O(Calld2)

这些空间用于保存有限的事实关系和入口到目标节点的对应。递归深度不会成为额外的存储维度；不同调用深度通过相同的路径关系与摘要复用。表中的空间上界由第 5 节给出，递归部分则是结合前述数据结构含义得到的解释。(Reps et al., 1995)
