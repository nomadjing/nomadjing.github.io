Lec01 · Welcome to GenSE

作品、能力与软件工程

Agent 降低了实现成本，软件工程仍要让系统在约束、变化和协作中持续满足人的目标。 Agent 能完成一份作业时，作品本身不再足以说明作者掌握了什么。课程因此追问：实现成本下降后，哪些能力仍值得学习？

课程将人的作用概括为「信息差、能坐牢、能驾驭」：知道计算机世界里有什么、为取舍承担后果、组织人和工具把事情做成。责任需要与实际的判断权和停止权相连；产出代码越快，发现错误、协调接口和验收结果越重要。

「禁止古法编程」鼓励把可委托的实现交给 Agent，腾出精力定义问题、理解关键机制和检查结果；它不意味着放弃理解代码。课程鼓励做出别人能打开、运行和继续使用的作品，用持续实践检验能力。

从语言模型到 Agent

从使用者角度，可以把自回归语言模型看作根据上下文预测下一个 token 的系统。输出会进入后续上下文，模型因而能逐步写下中间结果、检查和修正；流畅的回答仍不是正确性的证据。

Agent 在模型之外接入工具和环境，形成反馈循环：

目标与上下文 → 选择动作 → 调用工具 → 观察结果 → 更新上下文

它的能力取决于模型，也取决于工具能让它观察什么、操作什么，以及能否检查结果。承载指令、工具、权限和反馈的外围系统称为 harness。长任务还要考虑状态、重试与故障恢复；单步表现好，不能直接推出整个流程可靠。

先做出可观察的结果，再追问原理

可以先让 Agent 做出可操作、可检查的结果，再围绕遇到的问题学习配置和机制。「先用好」仍需验收实际行为，不能只听 Agent 宣称完成。

读书和读论文也是如此。Agent 可以整理材料、追踪主张与证据、寻找反例；摘要漂亮不代表自己已经理解。合上材料复述，再回原文查证，才能暴露自己的知识缺口。

[!tip] Insights 对低风险、能检查的数字任务，先问「能否交给 Agent 做出一个可观察的结果」。学习入口可以从记住全部步骤，变成判断结果并追问关键原理。

把一次成功变成软件资产

一次成功的操作还不是可复用的方法。重复任务需要明确的输入、操作、结果检查和失败处理；信息源、处理步骤与操作接口也可以组合。成功一次是演示；可检查、可修改、可重放的过程，才成为可复用资产。

课堂的办事大厅任务提供了一个具体路径：先让 Agent 探索页面，再把稳定流程写成脚本。浏览器不只有屏幕上的按钮，也有 DOM、请求、事件和状态；使用语义清楚的接口，通常比固定坐标点击更容易复现和检查。

Intent → Spec → Impl 的缺口

层次 含义 需要回答的问题
Intent（意图） 人想达成的效果，可能尚未想清 谁使用？什么结果才有价值？
Spec（规格） 明确的行为、约束和验收条件 输入范围、兼容性、失败时怎么办？
Impl（实现） 程序实际执行的确定动作 是否只对当前样例有效？

一个意图可以对应许多规格，一个规格也可以有许多实现。模型会用猜测填补空白；低影响的选择可以先做再验，高影响、难回滚的设计和验收口径需要先澄清。通过现有测试，只说明实现通过了那些检查，不说明规格忠实表达了意图。

**案例：二维码 Excel。**要求「任意字符串」隐含编码、分片、帧容量、刷新和重组等决定；硬编码版本能演示，却不能处理不同输入。这个案例说明，缺失的规格会变成未经审视的实现选择。改进需要可复用的计算结构，以及覆盖编码、扫码与拼接的验证；不能只检查文件能否打开。

[!tip] Insights 不要只按软件的名字判断它能做什么。Excel 也能计算并显示编码信息，屏幕和鼠标也能承载输入输出；重新认识已有部件的能力，可能带来新的解决路径。

让错误尽早显现

软件工程要把大目标拆成能检查的增量。每一步明确要消除的未知，用实际结果更新规格和设计，避免把许多未经检验的决定绑在一起。

代码生成变便宜，不会自动消除耦合、隐含约束和验证债。功能只改一点却要重新理解整套系统，是项目陷入「焦油坑」的信号。人的工作仍包括定义意图、决定哪些猜测可以接受、设计验收，以及在证据不足时及时调整方向。
